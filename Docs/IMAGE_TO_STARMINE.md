
# 画像から仮想星配置

玉内配置ワークベンチで手動レイヤーを選択しているときだけ「画像から生成」ボタンを表示する。画像選択後は点指定ダイアログを開き、被写体、除外背景、残したい特徴をユーザーが指定してから、現在の切断面へ編集可能な手動配置点として反映する。

## 確定仕様

- 点指定式では解析用画像を最長辺512pxへ縮小する。従来の即時抽出関数は互換テストのため最長辺256pxを維持する。いずれもブラウザ内だけで解析し、外部送信・保存データへの埋め込みは行わない。
- デコード前は20MB、デコード後は24メガピクセルを上限とし、EXIF向きを反映した `ImageBitmap` から表示用・解析用データを作る。
- 被写体点は1〜3点、背景除外点と特徴点は各0〜5点とする。被写体／背景点だけをマスクへ渡し、特徴点は仮想星の優先配点だけに使う。
- 点は元画像基準の正規化座標で保持する。CSS表示寸法、ズーム、パン、devicePixelRatioが変わっても座標は変えない。
- マスクはWorker内の点プロンプト対応軽量プロバイダで生成する。透過画像はアルファを優先し、不透明画像は被写体色、背景色、外周色、連結成分を使う。WorkerまたはOffscreenCanvasが使えない場合は同じ処理をメインスレッドのフォールバックで実行する。
- マスクはOpening/Closing後、被写体点を含む成分を保持する。順序付き輪郭を累積弧長で等間隔再サンプリングし、採用マスクの外接矩形を安全半径0.94へ収める。
- 特徴点の局所Sobelエッジへ優先配点する。通常は目標点数の25%、最大40%を特徴へ使い、外形へ常に60%以上を残す。局所エッジがない場合は特徴中心の小さな輪で示す。
- ダイアログは `role="dialog"`、`aria-modal="true"`、フォーカストラップ、Escape取消、元ボタンへのフォーカス復帰を持つ。画像キャンバスは矢印キー、Enter、Spaceでも操作できる。
- 確定前はdraftとUndo履歴を変更しない。確定時に開始時のレイヤーと切断面を使い、レイヤーの存在、手動種別、ロックを再検証して、成功時だけ1回の `updateIntent("画像から配置")` を行う。
- 外周画素の中央値から背景色を推定し、画像外周から洪水充填で「背景色に近く外周へ連結した領域」を背景とする。被写体に囲まれた背景色領域（白背景上の白い服など）は被写体側に残る。
- 被写体の連結成分を背景コントラストの合計で採点し、主要成分に対して弱い分離成分（壁の陰影の帯、切れた小片など）は配置対象から除外する。
- 画像の切れ目（被写体が画像端に接する箇所）は輪郭とみなさず、点を置かない。
- 点は被写体マスクの境界（アウトライン）と内部特徴に置く。目標点数の75%を境界へ等間隔で密に配置してアウトラインを強調し、残り25%を内部特徴（目など）のRGB Sobelエッジスコア順に割り当てる。特徴が少ない画像では余りを境界へ戻してさらに密にする。
- アウトラインの点はすべて同じ色にする。色は被写体マスク全体の最頻色（メディアンカット最大クラスタの代表色）とし、被写体の印象色で輪郭が一筆書きに見えるようにする。内部特徴の点は各自の色を使う。
- 目標点数は8〜240点、既定240点（2026-07-17に96点から変更）。同一画像・同一設定の結果は決定的にする。
- 配置先は現在の切断面で、生成結果は通常の `ManualLayerPoint` とする。移動、削除、仮想星の置換、Undo/Redoを既存操作のまま利用できる。
- 画像色は最大4色へ量子化し、常に既存の仮想星ライブラリの中で最も色の近い星へ割り当てる。画像由来の派生星は作らない。過去作品に残る `star-image-*` は割当先にせず、置換で未参照になれば除去する。
- 既存の「生成方法」（置換／追加）を共有する。
- ファイルサイズは20MB以下とし、被写体として8点以上を抽出できない画像はレイヤーを変更せず通知する。
- 保存形式はschema v4を維持する。

## マスクプロバイダ

2026-07-17時点では、追加のモデル重み、推論ライブラリ、WASM資産を配布せず、`PromptMaskProvider` 契約の `alpha` / `fast` / `fallback` 実装を採用した。画像データの外部通信はなく、通常起動時にモデルコードや重みを取得しない。Worker成果物はproduction buildで3.34kBだった。

SlimSAMなどの高精度モデルは、ライセンス、固定重み、ハッシュ、対象モバイルでのメモリと5秒以内の性能、50枚評価を満たす資産が確定していないため未採用である。後から `PromptMaskProvider` を差し替えられるよう、UI、点セッション、輪郭・特徴配点、保存形式をプロバイダから分離している。

- 2026-07-17改訂: [`reference/mao.png`](reference/mao.png)（白背景・左に壁の陰影帯があるイラスト）で輪郭が判別できない問題を修正した。原因は (1) 均一領域のSobel浮動小数点ノイズが特徴扱いされ内部に点が散っていた、(2) 全エッジを単一スコアで扱い黒い内部線が薄い外形輪郭より優先されていた、(3) 壁の帯と画像端のクロップ線が輪郭予算を浪費していた、の3点。エッジ下限しきい値（1階調）、洪水充填背景と輪郭優先予算、成分採点による分離ノイズ除外、画像端の非輪郭化で対応し、`mao.png`（頭部・猫耳・ツインテール・手が判別可能）と `latte.png`（耳までくっきり、クロップ線の点が消滅）を96点・240点で実機確認した。
