# 被写体・背景分離の精度向上 調査レポート

- 作成日: 2026-07-18
- 対象: CodexStarmine「画像から生成」のブラウザローカル処理
- 前提: 画像をサーバーへ送らず、ユーザーが被写体点・背景除外点・特徴点を指定する
- 関連資料: [`POINT_GUIDED_IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md`](plans/POINT_GUIDED_IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md)

## 1. 結論

精度とブラウザ実装の現実性を両立する推奨構成は、次の順で導入する。

1. **正点・負点に加えて矩形指定とマスクの即時プレビューを用意する。**
2. **SlimSAMを第一候補にし、1回の画像埋め込みからクリックのたびに3候補のマスクを再生成する。**
3. **モデルのIoU予測だけでなく、正点／負点の充足、閾値安定性、面積、境界コントラストで候補を選ぶ。**
4. **512pxへの縮小前に画像情報を失わないよう、モデル入力は最大辺1024pxを基本とする。失敗箇所は局所クロップで再推論する。**
5. **二値化前の確率マスクを保持し、連結成分選択とエッジに沿う境界補正を行う。**
6. **WebGPUが使えない端末ではWASM、モデルが使えない場合は改良版GrabCutまたは現行高速方式へ戻す。**

現行のRGB距離方式だけを調整しても、被写体と背景が同系色、背景が複雑、細い部位、影や反射がある画像では限界がある。短期的には現在の方式を改善できるが、主経路は学習済みのプロンプト式セグメンテーションへ移すべきである。

## 2. 現行実装の確認

### 2.1 現在できていること

- 通常経路は最大辺256px、点指定経路は最大辺512pxへ縮小する。
- 透過画像ではアルファを優先する。
- 被写体点と背景点から色を取得し、RGBユークリッド距離で全画素を分類する。
- 被写体点を含む連結成分だけを残す。
- 3×3のオープニングとクロージングで小さなノイズを除く。
- マスクから順序付き輪郭を作り、最終的に最大240個の仮想星へ変換する。
- セグメンテーションはWorkerで実行され、UIスレッドから分離されている。

### 2.2 精度上の主なボトルネック

| 現状 | 起こる問題 | 影響が大きい画像 |
| --- | --- | --- |
| クリック位置の1画素を代表色にする | ノイズ、ハイライト、影、圧縮誤差に弱い | 写真、JPEG、光沢物 |
| RGB距離だけで分類する | 色が同じ別物を区別できず、知覚上の色差とも一致しにくい | 同系色背景、模様、室内写真 |
| 背景色に画像外周の標本を使う | 被写体が画像端へ接すると被写体色が背景標本へ混ざる | アップ、全身が画面外へ出る画像 |
| 512pxで解析する | 1～3pxの細線、指、髪、アクセサリーが消える | イラスト、線画、細い部位 |
| 早い段階で二値化する | 迷いのある境界を後段で修正できない | 毛、半透明、ぼけた境界 |
| 一律3×3のオープニング | 幅1～2pxの正しい部位もノイズとして消す | アンテナ、尻尾、髪、ひも |
| 単一候補だけを採用する | 「物体全体」と「物体の一部」の曖昧さを解消できない | 人＋服、顔＋髪、乗り物＋車輪 |

特に `PromptMaskProvider.ts` の現在の判定は、被写体／背景の最短RGB距離と固定閾値に依存している。これは高速なフォールバックとしては有効だが、意味的な「同じ物体」を理解する処理ではない。

## 3. 精度を上げる方法

### 3.1 ユーザー入力を強くする

#### A. 正点と負点を反復入力する

現在の「被写体」「背景を除外」の点分けは正しい。最初の正点でマスクを出し、誤って含まれた場所へ負点、欠けた場所へ正点を追加する。画像エンコーダーの結果を再利用できるSAM系では、2点目以降は軽いマスクデコーダーだけを再実行できる。

実装上は、次を保証する。

- 正点は選択マスク内、負点はマスク外に入ることを候補選択の必須条件にする。
- マスク更新のたびに半透明オーバーレイを表示する。
- 直前の点をUndoでき、点をドラッグして修正できる。
- 画像上の点座標は常に原画像基準の正規化座標で保持する。

#### B. 矩形プロンプトを追加する

点だけでは「猫全体」か「猫の顔」かが曖昧になる。被写体を囲む矩形は、位置だけでなく期待する広がりも与えるため、複数候補がある画像に強い。SAMの公式ドキュメントも、点や矩形を与えると結果が大きく改善すると説明している。

推奨UIは次のどちらかである。

- 「被写体を囲む」モードでドラッグして矩形を作り、その後に正点／負点で修正する。
- 正点を1つ置いた後、マスクが低信頼のときだけ矩形を提案する。

#### C. ブラシ／短いストロークを第2段階で追加する

点を多数置かせるより、欠けた腕などを短い前景ストロークでなぞる方が速い場合がある。ただしSAM入力へはストロークを間引いた複数点として渡せるため、保存形式に自由線を残す必要はない。

最初から必須にはせず、50枚評価で4クリック以上を要する画像が多い場合に追加する。

### 3.2 プロンプト式モデルを使う

#### 第一候補: SlimSAM

SlimSAMは現時点で最も導入しやすい。

- Transformers.js向けONNX重みと、Hugging Face公式のWebGPUブラウザ例がある。
- 正点入力に対して3候補のマスクと予測IoUを返す。
- Apache-2.0。
- 量子化した画像エンコーダー8.88MBとデコーダー4.9MBの組み合わせは約13.8MBである。
- 画像エンコーダーとプロンプト／マスクデコーダーが別ファイルなので、クリック更新時に前者を再実行せずに済む。

弱点は、元のSAMや新しいSAM 2より小型化されており、難しい境界で品質が不足する可能性があることである。採用前に対象画像での実測が必要である。

#### 比較候補

| 候補 | 長所 | 短所・確認事項 | 判定 |
| --- | --- | --- | --- |
| SlimSAM | 約13.8MBの量子化構成、Transformers.jsのブラウザ例、Apache-2.0 | 小型化による精度低下を実画像で確認 | **第一候補** |
| MediaPipe Interactive Segmenter | 公式Web JS API、512入力モデル、確率マスクを返せる、WASM系の導入が容易 | 基本は1つの関心点、Solutions Preview、同期APIなのでWorker必須 | 比較PoC |
| MobileSAM | 9.66Mパラメータ、点／矩形、ONNX export、Apache-2.0 | 公開速度はGPU／CPU等でブラウザ値ではない。公式JS統合を別途作る | 第2候補 |
| EfficientSAM | ONNXのエンコーダー／デコーダー公開、Apache-2.0 | ブラウザWebGPUの公式実装と対象端末性能を要検証 | 第2候補 |
| EdgeSAM | 9.6Mパラメータ、点／矩形を含む蒸留、公式報告ではMobileSAMより高精度 | NTU S-Lab License 1.0。公開WebデモのONNX経路はPython側で、純ブラウザ実績ではない | ライセンス確認後 |
| SAM 2.1 tiny | SAMより画像精度が高い設計、点／矩形／マスク、Apache-2.0 | 38.9MパラメータでSlimSAMより大幅に重い。Transformers.jsはアーキテクチャを掲載するが、対象構成のブラウザ用重み・メモリ・速度をPoCで確認 | 将来候補 |
| GrabCut | 学習済み重み不要、矩形と前景／背景指定、OpenCV.jsで動かせる | 意味理解はなく、同系色や複雑なテクスチャに限界 | モデルなしフォールバック |

SAM 2.1の公式速度値はA100 GPU上の値であり、ブラウザ性能として使ってはいけない。tinyでも38.9Mパラメータあるため、本件ではSlimSAMと同列の初期候補ではなく、品質上限を調べる比較対象とする。

### 3.3 複数候補マスクを正しく選ぶ

SAM系は曖昧な1クリックに対して複数候補を返す。予測IoUが最大の候補を無条件に採用すると、ユーザーが意図した範囲と違う候補を選ぶことがある。

候補ごとに次を計算する。

1. **プロンプト充足**: 正点がすべて内側、負点がすべて外側か。
2. **モデル品質**: 予測IoUまたはquality score。
3. **安定性**: 二値化閾値を例として0.45、0.50、0.55へ変えたとき、面積と輪郭が大きく変わらないか。
4. **矩形整合**: 矩形外へ不自然に漏れていないか、矩形内を極端に小さくしか覆っていないか。
5. **境界整合**: 輪郭付近に原画像の色・輝度勾配があるか。
6. **前回マスクとの連続性**: 追加クリック前後で、修正箇所以外まで全面的に反転していないか。

優先順位は「プロンプト充足」を必須条件にし、その後にモデル品質と安定性を使う。面積は被写体が小さい画像もあるため、強い固定制約にはしない。

EdgeSAMではIoU tokenの信頼性が十分でないためstability scoreを推奨しており、この考え方はSlimSAMの候補選択にも有効である。

### 3.4 解像度を段階的に上げる

最大240点へ変換する場合でも、分離処理まで低解像度にする必要はない。輪郭抽出前に縮小すると、細い部位は点配分以前に消失する。

推奨処理は次の通り。

1. 原画像を1回だけデコードする。
2. モデル入力は最大辺1024pxを基本とし、モデル標準の前処理へ任せる。
3. 確率マスクをモデル解像度で保持する。
4. 誤境界へ追加された点の周辺だけ、原画像から512～1024px相当の局所クロップを作る。
5. 局所マスクを大域マスクへ合成する。
6. 最後に輪郭を抽出し、240点へ弧長サンプリングする。

端末性能への対策として、すべてを原解像度で処理するのではなく、通常1024px＋必要箇所だけ局所再処理とする。低メモリ端末では512pxへ落としてもよいが、ユーザーへ「省メモリ」状態を表示する。

### 3.5 確率マスクと境界補正を使う

#### 二値化を遅らせる

モデルから0～1の確率またはlogitを受け取り、後段まで保持する。固定0.5ではなく、次の条件で0.35～0.65程度を探索する。

- 正点を含み、負点を除外する。
- 閾値変更に対して安定している。
- 境界が原画像の強い勾配へ近い。

確率が0.4～0.6の領域を「不確実帯」として可視化すると、ユーザーは次にどこへ点を置くべきか判断しやすい。

#### エッジに沿って境界を補正する

モデルの粗いマスクから次のtrimapを作る。

- 確率0.9以上、または正点近傍: 確定前景
- 確率0.1以下、または負点近傍: 確定背景
- それ以外: 未確定

このtrimapをGrabCutへ渡し、原画像の色分布と境界勾配で数回だけ更新する。これにより、意味的な物体選択をモデル、画素単位の境界合わせをGrabCutへ分担できる。

#### 形態学処理を適応的にする

一律のオープニングは止め、次のルールへ変える。

- 透過PNGの高信頼アルファにはオープニングをかけない。
- 正点を含む細い成分は消さない。
- 除去する成分と穴は、固定1pxではなく画像面積比と点の有無で決める。
- クロージングは1～2pxの小さな切れ目だけに限定する。
- 輪郭の平滑化はマスク変更ではなく、輪郭ポリライン側で行う。

### 3.6 現行の高速方式を改善する

モデルを導入する前、またはモデルなしフォールバックでも次の改善が可能である。

1. **点ではなくパッチを標本にする。** クリック中心の5×5～11×11から中央値と分散を取り、エッジをまたぐ画素を除く。
2. **RGBからCIELABへ変換する。** 明るさと色差を分けて扱い、影に対する重みを調整する。
3. **単純な最近傍色から複数クラスタへ変える。** 前景／背景それぞれ2～5個の色クラスタまたはGMMを持つ。
4. **色だけでなく位置とエッジを使う。** 強い画像エッジをまたぐ分類を高コストにし、正点からつながる領域を優先する。
5. **GrabCutへ置き換える。** 矩形、正点、負点から確定／推定前景・背景を初期化し、3～5回反復する。

固定RGB閾値の微調整だけより、GrabCut化の方が改善余地は大きい。ただし学習済みモデルほど物体の意味は理解できないため、SlimSAMが動かない場合の経路と位置づける。

### 3.7 マッティングと専用モデル

髪、毛、煙、半透明布のように、1画素が前景と背景を混合している場合は、二値セグメンテーションではなくalpha mattingが必要になる。

ただし本機能の最終出力は最大240個の仮想星であり、連続アルファをそのまま表現しない。したがってマッティングの優先度は低い。次の場合にだけ別PoCとする。

- 被写体切り抜きプレビュー自体の品質が製品要件になる。
- 髪や毛の外形を240点へ単純化しても認識性が大きく上がる。
- 人物写真に用途を限定でき、人物専用モデルを許容できる。

### 3.8 ドメイン別学習

画像がアニメキャラクター、ぬいぐるみ、特定の商品などへ偏る場合、汎用モデルより専用ファインチューニングが効く可能性がある。SAM 2は公式に学習・ファインチューニングコードを公開している。

ただしデータ作成、学習、ONNX変換、量子化、ブラウザ検証、モデル更新管理が必要になる。まず汎用モデル＋ユーザー修正で失敗パターンを収集し、同じ失敗が繰り返される場合に限って行う。

## 4. 推奨アーキテクチャ

```text
原画像デコード
  ├─ 有効な透過alphaあり ──> alphaを高信頼初期マスクにする
  └─ RGB画像
        ↓
最大辺1024pxのモデル入力
        ↓
画像埋め込みを1回計算・Worker内に保持
        ↓
正点 + 負点 + 任意の矩形
        ↓
3候補マスク + 品質スコア
        ↓
プロンプト充足 + 安定性 + 境界で候補選択
        ↓
確率マスクをエッジ沿いに補正
        ↓
必要時のみ局所クロップで再推論
        ↓
点を含む連結成分・穴を整理
        ↓
順序付き輪郭 → 弧長配点 → 特徴点配点 → 最大240星
```

### 実行バックエンド

1. WebGPU + 量子化またはfp16モデル
2. WASM + 量子化モデル
3. GrabCut／改良高速方式
4. 最終的に現在の単純方式

ONNX Runtime WebではWASMが全ONNX演算子を対象にする一方、WebGPUなどのGPUバックエンドは対応演算子が部分的である。単なる `navigator.gpu` の有無ではなく、実際にセッションを作成して小さな推論が成功するかでバックエンドを決める。

モデル、WASM、設定は自前配信し、初回取得後はCache Storageで固定バージョンをキャッシュする。外部CDNを実行時の必須条件にしない。

## 6. 精度評価計画

### 6.1 データセット

最低50枚を手動の正解マスク付きで用意する。

- 透過PNG: 5枚
- 単純背景: 5枚
- 複雑背景: 10枚
- 被写体と背景が同系色: 5枚
- 人物・髪: 5枚
- 動物・毛: 5枚
- イラスト・線画: 5枚
- 画像端へ接する被写体: 5枚
- 複数被写体・分離部品・穴: 5枚

同じ画像について、1正点、1正点＋1負点、合計3点以内、矩形＋2点以内を比較する。

### 6.2 指標

| 指標 | 理由 |
| --- | --- |
| Mask IoU | 面積全体の一致度 |
| Boundary F1 | 輪郭位置の正しさ。細い部位の改善を見やすい |
| 正点／負点制約違反数 | ユーザー指示を守ったか |
| 目的マスクへ到達するクリック数 | 実際の操作負担 |
| 240点化後の輪郭距離 | マスク改善が最終出力へ残ったか |
| 被写体の分離成分保持率 | 腕、耳、車輪などの欠落を検出 |
| コールド取得時間／埋め込み時間／再クリック時間 | ブラウザUX |
| ピークメモリ／Worker破棄後メモリ | モバイル安定性 |

IoUだけでは、大きな胴体が合っていて細い尻尾が消えたケースを高得点にしやすい。Boundary F1と240点化後の輪郭距離を必ず併用する。

### 6.3 採用基準案

- 難しい画像の80%以上が、矩形を含め合計3操作以内で意図したマスクになる。
- 1正点＋必要な負点で、現行方式よりMask IoUとBoundary F1の中央値がともに改善する。
- 正点／負点の制約違反がない。
- 240点化後にも改善が残り、細部だけを増やして全体形状を悪化させない。
- 対象PCのWebGPUで、画像埋め込み後のクリック更新が体感待ちにならない。
- 対象モバイルのWASMまたはフォールバックで、クラッシュや長時間のUI停止がない。
- オフライン再訪時にモデルが再取得不要である。

性能の具体的なミリ秒上限は、対象端末を決めてベースラインを取ってから固定する。

## 7. 実装上の注意

- MediaPipeの `segment()` は同期呼び出しなので、公式案内どおりWorkerで実行する。
- クリックごとに画像エンコーダーを再実行しない。画像変更時だけ埋め込みを更新する。
- 古いrequestIdの結果は破棄し、最新の点集合だけをUIへ反映する。
- モデル推論の失敗、GPU device lost、メモリ不足を回復可能エラーとして扱う。
- GPUBuffer、Tensor、ImageBitmap、Object URL、Workerを明示的に破棄する。
- 透過alphaが信頼できる場合は、RGBモデルで品質を下げないようalpha経路を優先する。
- モデルの量子化形式ごとに精度を測る。ファイルが小さいことだけでint8を選ばない。
- モデルライセンスだけでなく、変換済み重みの配布条件と固定コミット／ハッシュも記録する。

## 8. 今回の推奨決定

1. 現行 `fast` は削除せず、即時プレビューと最終フォールバックに残す。
2. 次のPoCはSlimSAM量子化版をWebGPU／WASMで実装する。
3. UIへ任意の矩形プロンプトを追加する。
4. モデルの3候補を返すよう `PromptMaskProvider` の結果型を拡張し、候補選択をモデル外の純粋関数にする。
5. `SubjectMask` は最終二値マスクだけでなく、PoC中は確率値、品質、安定性、入力解像度を診断情報として保持する。
6. 点指定経路の解析上限を512pxから1024pxへ上げる。ただし通常の高速経路は256pxのままとする。
7. SlimSAMが50枚評価で不合格なら、MediaPipe Interactive SegmenterとEfficientSAMを比較する。
8. いずれのモデルも端末条件を満たさない場合は、パッチ標本＋CIELAB＋GrabCutを正式フォールバックにする。

## 10. 調査上の留保

- モデル間の公開精度値は、データセット、プロンプト条件、入力解像度、ハードウェアが異なるため横並び比較できない。
- MobileSAM、EdgeSAM、SAM 2の公開速度値はブラウザローカル計測ではない。
- WebGPU対応状況はブラウザ名だけでなくOS、GPU、ドライバで変わる。
- 本件の最終品質はマスクだけでなく240点への単純化にも左右されるため、公開ベンチマークよりプロジェクト固有の50枚評価を優先する。
