- 主設計資料: [RESEARCH.md 9章「花火制作工程と内部配置エディター」](../RESEARCH.md#9-花火制作工程と内部配置エディター)

- 対象: 製作モードのデータモデル、玉内配置UI、簡易検査、完成打上、保存・移行

## 1. 目的と完了像

現行の製作モードは、種類・号数・芯数・2色変化・尾・子花・昇曲をフォームで調整し、完成結果を打ち上げて確認する段階まで実装済みである。本強化では、これを「完成パラメーターを選ぶ画面」から、**玉皮を開き、火薬の玉を模した仮想星を手で仕込む感覚の制作画面**へ拡張する。

体験上の最優先事項は、制作意図を持てる一方で完成形を事前に見せすぎないことである。ユーザーは色、飛ぶ方向、発火順、時間差までは確認できるが、実際の花火の輪郭、軌跡、垂れ方、全体形状は「打ち上げる」まで見られない。狙いどおりになる期待と、自然な揺らぎで少し意外な結果になる不確実さを両立する。

完了時にユーザーが行えること:

1. 仮想星の発光・時間配色・尾・寿命を作る。
2. 玉皮の半球を開き、外周、芯、型物、子花の仮想星をつまむ・置く・列へ詰める感覚で配置する。
3. 断面と3D組立表示で層、密度、欠け、向き、空間配色を確認する。
4. ハートなどの型物をテンプレートまたは配置ガイドから作るが、空中で完成した形は表示しない。
5. 簡易確認では、色の順序、方向矢印、発火タイムライン、時間差だけを確認する。
6. 構成A/Bでは配置数と簡易検査結果だけを比較し、完成形の比較再生は行わない。
7. 制作を確定してエディターを離れた後、「打ち上げる」で初めて湖畔の完成結果を見る。
8. 既存プリセットと保存済みデザインを失わず、新しい編集形式へ移行する。

本機能は仮想花火の視覚デザインだけを扱う。玉皮や仮想星は実物らしい質感と配置感を持たせるが、実物の薬品、配合、点火、組立寸法、製造条件はデータにもUIにも導入しない。「火薬の玉」は画面上では常に「仮想星」と表記し、危険な実作業を教える画面にはしない。

## 2. 現状と設計上の差分

| 領域 | 現在の実装 | 強化で解消する差分 |
| --- | --- | --- |
| データ | `FireworkDesign` に全粒子共通の `colorStages` / `trailStyle` と、簡略化した `coreLayers` / `childBursts` を保持 | 仮想星定義、レイヤー、星割り当て、型物点群、固定シードを明示する |
| 開花生成 | `FireworkSystem` が `burstShape` を分岐し、外周・芯・子花を直接生成 | レンダリング非依存のコンパイラが全レイヤーを再現可能な点群・速度へ変換する |
| 再現性 | 球・ハート・椰子の初期点群はseed対応だが、寿命・子花遅延・煙などに `Math.random()` が残る | 組立配置は安定させ、本番打上では意図を壊さない範囲の揺らぎseedを別に与える |
| 製作ロジック | `CraftController` が1つのdraftへ直接代入 | 編集ドキュメント、選択状態、コマンド履歴、検証結果を分離する |
| UI | `AppShell` 内の単一フォームと単発プレビューボタン | 仮想星の部品皿、半球の組立台、断面、属性インスペクター、簡易検査へ分割する |
| 事前確認 | 湖畔へ打ち上げ、実際の開花形状を何度でも見られる | 制作中は色・方向・タイミングだけを表示し、完成形は確定後の打上まで隠す |
| 保存 | `codex-starmine.designs.v1`、ライブラリversion 1 | version 2を追加し、v1を非破壊で自動移行する |
| 負荷管理 | 実行時の `MAX_STARS = 6000` で古い粒子を切り捨て | 保存前に推定コストと簡略化候補を表示する |

既存の6プリセット、3サイズ、フリー鑑賞、音・煙・湖面反射は回帰対象とし、本強化後も同じ `FireworkDesign` の完成物を利用できる状態を維持する。

## 3. 実装範囲

### 3.1 今回の必須範囲

- 仮想星ライブラリ: 単色、変化、炭火引、金引、銀引、点滅、長寿命、子花
- 星タイムライン: 1〜4段階の色・輝度・尾色、寿命、尾、点滅、重力、抗力
- レイヤー: 外周球面、芯1、芯2、平面型物、子バースト
- 配置: Fibonacci sphere、緯度帯、手動点群、配置ゆらぎ、欠け率
- 空間配色: レイヤー一括、選択範囲、緯度帯、経度セクター、交互色
- 型物: ハートテンプレート、ペン、直線、円、ベジェ曲線、再サンプル、部位グループ
- 向き: 正面優先、会場正面固定、ランダム、奥行き、回転ゆらぎ、0/30/60/90度確認
- 子花: 親 + 子の2階層まで、数、配置、遅延、色、スケール
- 編集支援: Undo/Redo、内部assembly seed、簡易A/Bスナップショット、レイヤー表示切替、負荷警告
- 組立感: 半球状の玉皮、仮想星の部品皿、ドラッグ配置、列詰め、層ごとの仕切り、左右半球の切替
- 簡易検査: 色列、方向ベクトル、発火タイムライン、時間差、負荷だけを表示する非写実プレビュー
- 完成打上: 保存・確定後にエディターを離れ、生成した本番seedで初めて完成形を表示する
- 既存保存データの自動移行と、旧データを残したままの安全な書込み

### 3.2 後続へ送る範囲

- SVGファイルのインポート
- 文字組み・フォントからの型物生成
- 自由曲面へ描く本格的な3Dペイント
- 子花の孫以下への再帰
- 三重芯以上、複数平面を組み合わせる立体型
- クラウド同期、共同編集、作品共有
- ショータイムラインと音楽連動モード自体の編集機能
- エディター内での実際の開花形状、粒子軌跡、煙、音、湖面反射のプレビュー

## 4. 制作フローと画面構成

### 4.1 制作フロー

現行の「種類 → 大きさ → 芯 → 色 → 尾 → 子花 → プレビュー」は、完成形を直接見せない制作フローへ置き換える。

1. **作品**: 名前、説明、テーマ色、系統、号数を設定する。
2. **仮想星を選ぶ**: 色、色変化、尾、寿命を持つ球状パーツを部品皿から選ぶ。
3. **玉へ仕込む**: 開いた半球の外周、芯、型物、子花の位置へ仮想星を置く。自動整列は手作業を補助する道具として提供する。
4. **開き方を決める**: 広がる方向、整然さ、重力、抗力、時間差を結果ではなく矢印と数値で調整する。
5. **簡易検査する**: 色列、方向矢印、発火タイムラインを再生し、A/Bで構成差だけを比較する。
6. **制作を確定する**: 警告を確認し、完成形ではなく玉の断面サムネイル付きで保存する。
7. **打ち上げる**: エディターを離れて湖畔へ遷移し、この時点で生成したlaunch seedによる完成形を初めて鑑賞する。

プリセットから始めた場合も「一から作る」を選んだ場合も、同じ編集ドキュメントへ到達させる。簡易フォームで変更した値と詳細編集の内容が別々に存在する二重管理は作らない。

### 4.2 デスクトップ配置

| 領域 | 内容 |
| --- | --- |
| 左 | 制作工程、外周・芯などの層一覧、色と効果別の仮想星部品皿 |
| 中央 | 半球組立 / 断面 / 型物配置 / 簡易確認の切替ワークベンチ |
| 右 | 選択中の作品・レイヤー・星・型物・子花の属性インスペクター |
| 下 | Undo/Redo、半球切替、回転、配置補助、簡易検査の再生、構成A/B、制作確定 |

モバイルでは左・右領域をドロワー化し、半球組立台と主要操作を優先する。390 × 844でも、仮想星選択、配置、簡易検査、保存を横スクロールなしで完了できることを最低条件とする。

### 4.3 4つの制作表示

- **半球組立**: 開いた玉皮を斜め上から見せ、球状の仮想星をドラッグして内壁のガイドへ置く。紙質、影、球の詰まり方で手仕事感を出す。
- **断面**: 同心層、仕切り、中心からの相対位置を図解する。実寸や実材料ではなく比率だけを扱う。
- **型物配置**: 半球内の配置ガイドへ星を並べ、部位グループを編集する。空中に開いた完成図形は表示しない。
- **簡易確認**: 色チップがタイムライン上を進み、方向矢印が順番に点灯する。位置、粒子軌跡、重力落下、煙、音、花火の輪郭は描かない。

断面・型物配置・簡易確認はSVGで実装し、DOMイベント、キーボード操作、拡大時の輪郭、テスト容易性を確保する。半球組立だけをthree.jsへ寄せる。簡易確認は意図的に `FireworkSystem` を利用せず、完成形を描画できない依存関係にする。

## 5. データとアーキテクチャ

### 5.1 一方向の変換パイプライン

```text
CraftDocument
  └─ FireworkDesignV2 + selection + history + assembly state
       ├─ validateDesign()
       │    └─ buildEditorDiagnostic()
       │         └─ 色列 + 方向集計 + 発火タイムライン + 警告
       └─ save / confirm
            └─ launch sceneでlaunch seedを生成
                 └─ compileFireworkDesign(design, launchSeed)
                      └─ FireworkSystemの本番打上
```

エディターには `CompiledBurstPlan` を渡さない。`buildEditorDiagnostic` は完成点群を色、方向区分、時刻区分へ不可逆に集約し、花火形状へ戻せないデータだけを返す。本番打上だけが保存デザインとlaunch seedから `CompiledBurstPlan` を生成する。内部配置と本番結果の対応は共通の保存デザインから保証しつつ、表示経路を分離して意外性を守る。

### 5.2 `FireworkDesign` version 2

既存のトップレベル値を即座に削除せず、移行期間はv1型とv2型を判別可能にする。v2の中心構造は次のとおりとする。

```text
FireworkDesignV2
  schemaVersion: 2
  id, name, description, themeColors[]
  family, pattern, sizeClass, ascentEffect
  starDefinitions{}       デザインが参照する仮想星の固定スナップショット
  layers[]                表示順を持つ判別共用体
  burstField              基本速度、重力、抗力、風応答
  realism                 配置/速度/発火/寿命のゆらぎ、欠け率
  assemblySeed            自動整列を安定させる制作seed
  launchVariation         意図を壊さない本番揺らぎの範囲
  soundProfile, smokeProfile
```

`layers[]` は共通の `id`、`name`、`visible`、`locked`、`ignitionOffset`、`radialSpeedScale` を持ち、次の型へ分ける。

- `SphericalStarLayer`: 半径比、配置方式、星数、既定星、配置seed、ゆらぎ、欠け、選択グループ、疎な個別上書き
- `PatternStarLayer`: 正規化パス、再サンプル間隔、部位グループ、奥行き、向きポリシー、星割り当て
- `BranchStarLayer`: 椰子プリセット互換の枝数、上向き量、枝内星数、太さ
- `ChildBurstLayer`: 子デザインの固定スナップショット、配置方式、数、遅延、スケール、向き

星を数百個すべてJSONへ展開せず、球面や型物は**生成規則 + seed + 疎な上書き**として保存する。手動点群だけ座標を保存する。これによりUndo、保存容量、星数変更時の再生成を扱いやすくする。

`VirtualStarPreset` はRESEARCH 9.4の値を持つ。作品保存時には参照中の星定義を `starDefinitions` へ複製して固定し、後から仮想星ライブラリを編集しても過去作品が変化しないようにする。

### 5.3 決定的な開花コンパイラ

`compileFireworkDesign` はレンダリングに依存せず、次を返す。

```text
CompiledBurstPlan
  stars[]
    id, layerID, initialPosition, initialVelocity
    presetID, timingOffset, intensityScale
  childBursts[]
  bounds
  estimatedCost
  warnings[]
```

要件:

- 同じデザインとlaunch seedからは、星位置、速度、寿命係数、発火差、子花遅延まで同じ結果を生成する。
- Fibonacci sphereは要求数どおりの単位球面点を生成し、極へ集中しない。
- レイヤー半径比は初期速度へ写像し、断面の芯半径と観客視点の開花径を一致させる。
- 型物は `orientation * scaleMatrix * (p - center)` を基本速度へ使う。
- 星プリセットごとの時間配色、尾、寿命、重力、抗力を粒子単位で渡す。
- 非表示レイヤーは簡易検査から除外できるが保存時には残す。
- 本番launch seedは制作確定後に生成し、配置・速度・寿命・発火へ設定範囲内の揺らぎを与える。玉名や型物の主題を壊す揺らぎは禁止する。
- A/Bは `EditorDiagnostic` の色、方向、時刻、負荷だけを比較し、`CompiledBurstPlan` や本番画像を表示しない。

現在 `FireworkSystem.#emitBurst` が担う形状分岐と芯・子花生成をコンパイラへ移し、`FireworkSystem` はコンパイル済みの星・子バーストを再生する責務へ縮小する。

### 5.4 編集ドキュメントとUndo/Redo

フレームワークは追加せず、購読可能な `CraftDocumentStore` と編集コマンドを実装する。

- 永続化対象: `FireworkDesignV2`
- 履歴対象: デザインを変える操作だけ
- 一時状態: 選択、カメラ、ズーム、開いているタブ、ホバー、再生時刻
- コマンド: レイヤー追加/削除/並替、半径変更、星割当、パス編集、グループ操作など
- スライダーとドラッグ: pointer開始から終了までを1履歴へまとめる
- 履歴上限: 100操作。保存後も現在セッション中は履歴を維持する
- キー操作: `Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z`、Delete、Escape

`CraftController` は互換用の入口として段階的に薄くし、最終的に保存・プリセット選択などのユースケースを `CraftDocumentStore` へ委譲する。

### 5.5 保存形式とv1移行

新しい保存先は `codex-starmine.designs.v2` とし、次の順で読み込む。

1. v2があれば検証して読む。
2. v2がなくv1があれば、メモリ上でv2へ移行する。
3. 移行結果を検証できた場合だけv2へ書く。
4. v1キーは削除しない。ロールバック用バックアップとして残す。
5. 一部デザインの移行に失敗した場合、成功分だけで上書きせず、ユーザーへ警告しv1読込へ戻す。

v1からの変換規則:

| v1 | v2 |
| --- | --- |
| `colorStages`、`trailStyle`、`burnDuration`、粒子物理 | 外周用の仮想星定義 |
| `particleDensity`、`symmetry` | 外周の `SphericalStarLayer` とrealism |
| `coreLayers[]` | 半径と色を保った芯レイヤー + 芯用仮想星 |
| `burstShape: heart` | 組込みハートパスを持つ `PatternStarLayer` |
| `burstShape: palm` | `BranchStarLayer` |
| `childBursts[]` | `ChildBurstLayer` |
| その他の球形 | `SphericalStarLayer` |

移行前後を同じseedでコンパイルし、プリセットごとに星数、主要色、開花境界、芯数、子花数が許容差内で一致する回帰テストを用意する。

E0 → E1 → E2 → E3 → E4 → E5 → E6 → E7

## 10. テストと検証

### 10.1 自動テスト

- **Vitest**: スキーマ検証、v1→v2移行、seed再現性、Fibonacci sphere、レイヤー独立性、パス再サンプル、姿勢変換、子花階層、負荷見積り、Undo/Redo
- **既存回帰**: 粒子物理、色補間、ShowCue、保存処理の既存テストを維持する
- **ブラウザE2E**: Editor Phase 2でPlaywrightを追加し、半球への仮想星配置、制作例2種、保存再読込、Undo/Redo、簡易A/B、確定後の初回打上、モバイル操作を自動化する
- **依存境界テスト**: 製作画面が `FireworkSystem`、粒子軌跡、煙、音、湖面反射を読み込まず、`EditorDiagnostic` だけを描画することを確認する
- **構造確認**: 保存JSONに未知フィールドや実物の材料・配合・製造条件が入らないことを確認する

各Phaseの最低確認コマンド:

```bash
rtk npm run lint
rtk npm run test:run
rtk npm run build
rtk npm run test:e2e  # Editor Phase 2で追加後
```

### 10.2 目視・性能確認

- 変化八重芯菊: 半球と断面で3層へ異なる仮想星を仕込み、簡易確認には色順・方向・時刻だけが出る
- 2色ハート: 玉内で左右の星色と正面方向を設定できるが、完成ハート形状は表示されない
- 千輪: 子花数と遅延差が簡易タイムラインへ反映されるが、開花密度の完成像は表示されない
- A/B: 星数、色列、方向区分、発火時刻だけを比較し、完成点群や軌跡を生成しない
- 10号八重芯の簡易検査は入力後100ms以内に更新される
- 制作確定までは花火形状が一度も表示されず、湖畔へ遷移後の打上で初めて確認できる
- 本番単発はデスクトップ基準環境で60fps、モバイル基準環境で30fpsを下回り続けない
- 推定同時星数2,000超で警告、実行時上限6,000超で簡略化を必須にする。閾値は実測後に定数と文書を同時更新する

## 11. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| v2化で保存作品が消える | ユーザー作品を失う | 新キーへ書き、v1を削除しない。全件成功時だけ移行確定する |
| 簡易確認が完成形を見せる | 意外さと打上前のドキドキ感が失われる | エディターは不可逆に集約した `EditorDiagnostic` だけを受け取り、`FireworkSystem` への依存を禁止する |
| 玉内配置と本番結果が無関係に見える | 制作意図を持てない | 同じ保存デザインから本番をコンパイルし、揺らぎを設定上限内へ制限する |
| 個別星を保存して容量が膨らむ | localStorage上限に達する | 生成規則 + seed + 疎な上書きで保存し、容量を事前表示する |
| `Math.random()` が比較へ混入する | A/Bが成立しない | 比較対象の乱数を共通seed源へ集約し、テストで禁止箇所を監視する |
| 巨大な `AppShell` が変更競合を起こす | UI追加のたびに回帰する | モード枠、ワークベンチ、各パネルへ所有権を分割する |
| 3D選択とSVG編集が別状態になる | 表示切替で選択や変更が失われる | `CraftDocumentStore` を唯一の編集状態にする |
| 実物らしい組立表示が製造手順に見える | 安全面と製品意図を誤解される | 仮想星・相対比だけを扱い、材料名、配合、実寸、点火、製造条件を排除する |
| 型物の細部が開花時に読めない | 打上後に狙いが伝わらない | 完成形を見せず、最小間隔、向き、許容角度だけを数値警告する |
| A/Bが情報過多になる | 比較から完成形を推測しやすくなる | 色・方向区分・発火時刻・負荷だけへ比較項目を限定する |

## 12. git運用

Editor Phaseごとに最低1コミット、機能単位で分割する。

例:

- `test(editor): v1デザインの回帰fixtureを追加`
- `feat(editor-model): FireworkDesign v2と移行処理を追加`
- `feat(editor-core): 内部配置コンパイラを実装`
- `feat(editor-ui): レイヤーワークベンチを実装`
- `feat(editor-pattern): 型物の点群編集を実装`
- `feat(editor-diagnostic): 色・方向・発火時刻の簡易検査を実装`
- `feat(editor-launch): 制作確定後の初回打上導線を実装`

各Phase完了時は、自動テスト結果、ブラウザ確認サイズ、制作した受け入れ作品名をコミット本文または計画書の完了確認へ残す。
