# 「画像から仮想星を生成」整理・改良計画書

- 作成日: 2026-07-19
- ステータス: 主要機能実装済み・追加性能計測を継続
- 対象: 玉内配置ワークベンチの手動レイヤー
- 現行仕様: [IMAGE_TO_STARMINE.md](../IMAGE_TO_STARMINE.md)
- 既存計画: [POINT_GUIDED_IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md](POINT_GUIDED_IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md)

## 1. 目的

「画像から仮想星を生成」を、被写体の外形だけでなく、髪と顔、服と肌、模様と地色など、画像内の主要な色領域の境界も花火として読み取れる機能へ改良する。

今回の改良では次を同時に行う。

1. 被写体を8色以内へ減色し、色領域同士の境界を「内部境界」として抽出する。
2. 配置モードを外形・内部境界・内部充填の3段階へ整理する。
3. 目標点数をスライダーで操作できるようにし、既定1024点・最大2048点へ拡張する。
4. 仮配置点を役割別の高視認色で表示する。
5. 推論モデル方式と古典方式で、必要な領域選択操作だけを表示する。
6. モデルロード、推論、減色、配点中の状態をダイアログ下部へ集約し、処理中アニメーションを表示する。

確定後は従来どおり通常の `ManualLayerPoint` と画像由来の仮想星定義だけを保存し、元画像、マスク、減色ラベル、内部境界、UI設定は保存しない。保存schemaはv4のままとする。

## 2. 完了状態

- 配置範囲に次の3モードが表示される。
  - `輪郭のみ`
  - `輪郭＋内部境界`
  - `輪郭＋内部境界＋内部`
- 既定モードは `輪郭＋内部境界` である。
- 被写体マスク内を最大8色へ減色し、異なる代表色が接する線上へ内部境界点が並ぶ。
- `mao.png` などで、髪と顔、髪と服のような主要色領域の境界が外形とは別の点列として判別できる。
- 目標点数は数値入力とスライダーの両方で8〜2048点を選べ、既定値は1024点である。
- 外形、内部境界、内部点がプレビュー上で見分けられる。
- 推論モデル方式では `被写体を囲む` と `被写体` だけを表示する。
- 古典方式では `被写体を囲む`、`被写体`、`特徴`、`背景を除外` を表示する。
- 処理状態はヘッダーではなくダイアログ下部に表示され、処理中はアニメーションと状態文が見える。
- 取消は処理中も可能で、配置は有効な最新結果が完成するまで無効である。
- 同一画像、同一指定、同一設定からは同一の点列、色、星IDが生成される。

## 3. 現行実装との差分

| 項目 | 現行 | 改良後 |
| --- | --- | --- |
| 配置モード | 輪郭のみ／輪郭＋内部 | 3モードへ再編、内部境界を追加 |
| 既定モード | 輪郭のみ | 輪郭＋内部境界 |
| 既定点数 | 240 | 1024 |
| 最大点数 | 1024 | 2048 |
| 点数UI | 数値入力 | スライダー＋数値入力 |
| 8色減色 | 内部・特徴の採用点だけを量子化 | 被写体マスク全体を8色へ減色し、画素ラベルを保持 |

## 4. 用語とデータ契約

### 4.1 配置点の役割

```ts
export type GuidedPlacementPointKind =
  | "outline"
  | "internal-boundary"
  | "interior"
  | "feature";

export type GuidedPlacementMode =
  | "outline"
  | "outline-internal-boundary"
  | "outline-internal-boundary-filled";
```

- `outline`: 被写体マスクと背景の外形境界。
- `internal-boundary`: 被写体内で異なる減色ラベルが接する境界。
- `interior`: 境界から離れた被写体内部の充填点。
- `feature`: 古典方式でユーザーが明示した特徴点。

### 4.2 設定型

`fillInterior: boolean` は表現力が不足するため、一時設定を `placementMode` へ置き換える。

```ts
export interface GuidedImagePlacementSettings {
  enhanceDarkColors: boolean;
  imageStarKind: ImageDerivedStarKind;
  outlineStar?: GuidedOutlineStar;
  placementMode: GuidedPlacementMode;
  targetCount: number; // 8...2048
}
```

この設定はダイアログを開き直したときのセッション内初期値として保持してよいが、作品データには保存しない。

### 4.3 減色画像

```ts
export interface QuantizedSubjectMap {
  height: number;
  labels: Uint8Array; // 0...7、マスク外は255
  palette: number[]; // RGB、最大8色
  width: number;
}

export interface InternalColorBoundary {
  colorA: number;
  colorB: number;
  length: number;
  points: Array<{ x: number; y: number }>;
}
```

現行の `quantizeImageColors()` は入力点の色列を量子化する関数として残せるが、内部境界抽出には被写体マスク全体の代表色とラベル画像を返す新しい純粋関数を使う。

### 4.4 診断情報

```ts
export interface GuidedPlacementDiagnostics {
  featurePointCounts: Record<string, number>;
  interiorPointCount: number;
  internalBoundaryCount: number;
  internalBoundaryPointCount: number;
  maskProvider: SegmentationProvider;
  maskRevision: number;
  outlinePointCount: number;
  paletteColorCount: number;
  totalPointCount: number;
}
```

`GuidedImagePlacementResult` には保存対象外の `pointKinds` を追加し、プレビュー描画で点の役割を判別できるようにする。

## 5. 8色減色と内部境界抽出

### 5.1 処理順序

```text
元画像
  → 被写体マスクの確定・整形
  → マスク内画素だけから代表色を最大8色抽出
  → 各マスク内画素を代表色ラベルへ割当
  → ラベル画像の小領域・孤立ノイズを整理
  → 隣接する異色ラベルを内部境界候補化
  → 外形近傍と短すぎる境界を除外
  → 順序付き線へ追跡・簡略化
  → 累積弧長で等間隔配点
```

明色補正は内部境界の判定前には行わない。境界は元画像の色関係から作り、明色補正は画像由来の仮想星定義を作る直前だけに適用する。これにより補正のオン／オフで形状が変わらず、星の見え方だけが変わる。

### 5.2 代表色の算出

1. 対象は整形済み被写体マスク内の不透明画素だけとする。
2. 大画像では全画素をそのままメディアンカットへ渡さず、決定的な格子サンプリングで最大65,536色を集める。
3. 現行と同系統のメディアンカットで最大8色を得る。
4. 各マスク内画素を最も近い代表色へ割り当て、`labels` を作る。
5. 色距離は単純なRGB距離ではなくOKLab距離を使う。追加ライブラリは導入せず、小さな変換関数を純粋関数として実装する。

代表色が8色未満しかない画像では、存在する色数だけを使う。空クラスタを水増ししない。

### 5.3 ラベル画像のノイズ抑制

減色しただけでは髪のハイライト、JPEGノイズ、細かな陰影が多数の短い境界を作るため、境界抽出前に次を行う。

1. 3×3の多数決フィルターを1回適用する。
2. マスク面積の0.1%未満かつ32px未満の小領域を、接触長が最も長い隣接ラベルへ統合する。
3. 1px幅の孤立線や単独画素を除く。
4. 被写体点を含む領域や、画像短辺の3%以上の長さを持つ細長い領域は、単純な面積だけで削除しない。

閾値は分析画像解像度に対する比率を主とし、固定px値は下限として扱う。

### 5.4 内部境界候補

- 4近傍で異なる有効ラベルが接する辺を境界セグメントとする。
- マスク外との境界は `outline` であり、内部境界には含めない。
- 外形から分析画像上2px以内の内部境界候補は除き、外形点との二重線を防ぐ。
- 同じ2色の組み合わせごとにセグメントを接続する。
- 分岐点では接線方向の変化が最小になる組み合わせを優先し、短い枝は別輪郭として扱う。
- 長さが画像短辺の2%未満の境界は原則として除外する。ただし古典方式の特徴点から2%以内を通る境界は残せる。

### 5.5 線の簡略化と配色

- 内部境界も外形と同様に順序付き点列と累積弧長を持つ。
- Douglas–Peucker相当の簡略化許容値は分析画像の1px相当から開始する。
- 配点は画像走査順ではなく、累積弧長に沿う等間隔配置とする。
- 1本の内部境界に接する2つの代表色を保持する。
- 内部境界上の仮想星色は、境界の両側の代表色を点順に交互に割り当てる。髪色と肌色の双方を残し、単一色の線に見えることを避ける。
- 交互割当の開始側は色番号と輪郭キーから決定し、毎回同じ結果にする。

## 6. 配置モードと点数配分

### 6.1 モード

| 値 | UI名 | 外形 | 内部境界 | 内部充填 | 既定 |
| --- | --- | --- | --- | --- | --- |
| `outline` | 輪郭のみ | あり | なし | なし |  |
| `outline-internal-boundary` | 輪郭＋内部境界 | あり | あり | なし | ✓ |
| `outline-internal-boundary-filled` | 輪郭＋内部境界＋内部 | あり | あり | あり |  |

古典方式の明示特徴点は選択モードにかかわらず保持する。特徴点数を最初に総予算から引き、残りを下表で配分する。

### 6.2 既定配分

| モード | 外形 | 内部境界 | 内部 |
| --- | ---: | ---: | ---: |
| 輪郭のみ | 100% | 0% | 0% |
| 輪郭＋内部境界 | 45% | 55% | 0% |
| 輪郭＋内部境界＋内部 | 30% | 40% | 30% |

既定1024点の場合、`輪郭＋内部境界` は外形約461点、内部境界約563点を初期予算とする。

配分は最終点数の厳密な固定ではなく、次の再配分規則を持つ。

1. 外形と内部境界の各カテゴリ内では、輪郭長に比例して予算を配る。
2. 有効な内部境界がない場合、`輪郭＋内部境界` の余剰は全て外形へ戻す。
3. 充填モードで内部境界がない場合、余剰は内部70%・外形30%で再配分する。
4. 短い輪郭へ同一点を重ねない。輪郭長に対して点数が多すぎる場合は、余剰を次のカテゴリへ回す。
5. 内部点は外形・内部境界・特徴点から分析画像2px相当以上離す。
6. 最終点数は候補不足の場合を除き、指定点数と一致させる。

現行の `GUIDED_FILLED_OUTLINE_MAXIMUM_POINTS = 240` による固定上限は廃止し、モード別比率と候補密度で配分する。

## 7. 目標点数UI

### 7.1 値

- 最小: 8
- 最大: 2048
- 既定: 1024
- スライダー刻み: 8
- 数値入力: 任意整数を受け付け、確定時に8〜2048へクランプする

汎用の `DEFAULT_IMAGE_PLACEMENT_SETTINGS` を不用意に変更せず、点指定ダイアログ用の既定値を `DEFAULT_GUIDED_IMAGE_PLACEMENT_SETTINGS.targetCount = 1024` として明示する。上限定数は適用処理とUIで共通化する。

### 7.2 表示

```text
目標点数                         1024点
[────────────●────────────────]
[ 1024 ]
```

- `range` と `number` は同一値を双方向同期する。
- スライダー操作中は `input` イベントで表示値を更新する。
- 重い再配点は80〜120msのデバウンス後に最新値だけ実行する。
- `aria-label="目標点数"`、`aria-valuetext="1024点"` を設定する。
- キーボードの矢印は8点、PageUp/PageDownは128点単位で変更できる。
- 最大2048点では既存の描画負荷メーターに反映し、作品全体の粒子上限警告を消さない。

## 8. 仮配置点の表示

現行のオーバーレイは全配置点を同じ金色で描くため、何が外形で何が内部か判断できない。最終的な仮想星色とは独立した、役割を示す高視認色を使う。

| 点種別 | 仮表示色 | 用途 |
| --- | --- | --- |
| 外形 | シアン `#57D9FF` | 被写体シルエット |
| 内部境界 | マゼンタ `#FF5CC8` | 髪・顔などの色境界 |
| 内部 | 黄 `#FFD84D` | 面の充填 |
| 明示特徴 | ライム `#8CFF72` | 古典方式の特徴指定 |

- 点には暗色背景用の外側グローと、明色画像用の1px濃色縁取りを付ける。
- 点半径は分析画像幅に比例させるが、表示上1.5〜4pxへクランプする。
- 設定欄または診断欄に4色の小さな凡例を表示する。
- 選択中モードに存在しないカテゴリは凡例から隠す。
- 不確実領域の琥珀色ハッチは点種別色と混同しないよう現行のまま維持する。
- `pointKinds` と点列のインデックスを必ず揃え、色だけでなく診断テキストでもカテゴリ別点数を表示する。

## 9. 領域選択UIの整理

### 9.1 操作プロファイル

```ts
export type SegmentationInteractionProfile = "model" | "classic";
```

| プロファイル | 表示する操作 |
| --- | --- |
| `model` | 被写体を囲む、被写体 |
| `classic` | 被写体を囲む、被写体、特徴、背景を除外 |

推論モデル方式では、内部境界を自動抽出するため `特徴` を表示しない。SlimSAM候補選択へ負点を渡す現行機能より、ユーザーの要求どおり操作の単純さを優先して `背景を除外` も表示しない。

### 9.2 プロファイルの決定

- `SegmentationMode = "auto"` の開始時は `model` とする。
- `SegmentationMode = "fast"` は `classic` とする。
- `slimsam` は `model`、`fast` と `grabcut` は `classic` として診断表示する。
- 有効alpha画像はモデルロードを行わないが、操作を簡潔にするため `model` 相当の2操作とする。
- `auto` が恒久的に古典方式へフォールバックした場合は `classic` へ切り替え、特徴と背景除外を表示する。その際は「軽量方式へ切り替えました。必要なら特徴・背景を追加できます」と通知する。
- モデル準備中の一時的なfastプレビューだけでは、操作タブを切り替えない。要求モードが確定してから変更する。

`ImageSegmentationClient` は現在の要求モードと確定プロバイダをダイアログへ通知する契約を追加する。URLの `?segmentation=fast` は回帰確認用として維持する。

### 9.3 状態切替時の安全性

- 非表示操作は `hidden` とし、フォーカス順とアクセシビリティツリーから外す。
- プロファイルが `model` のとき、`feature` と `background` はマスク要求にも配点にも使わない。
- 既存セッションで古典方式からモデル方式へ切り替える経路を将来追加する場合は、非表示になる点を削除する前に確認する。
- キーボード操作の説明文と `aria-label` は表示中の操作だけを列挙する。
- `PROMPT_LABELS`、点一覧、Undo履歴の内部型は4種類のまま保持し、古典方式の回帰を防ぐ。

  | "awaiting-subject"

  | "quantizing-colors"

- スピナーはCSSのみで実装し、`prefers-reduced-motion: reduce` では回転を止めて静的な状態記号へ切り替える。
- 状態更新を短時間に連続して読み上げないよう、同一文言を重複設定しない。

## 11. 非同期処理設計

最大1024pxの被写体全体を8色へ割当し、最大2048点を再構築すると、メインスレッド上ではスピナーが停止する恐れがある。減色、ラベル整理、内部境界追跡、配点はWorkerで実行する。

### 11.1 新規Worker契約

```ts
type PlacementWorkerRequest = {
  image: ImageDataLike;
  mask: SubjectMask;
  prompts: ImagePrompt[];
  requestId: number;
  revision: number;
  settings: GuidedImagePlacementSettings;
  type: "build-placement";
};

type PlacementWorkerResponse =
  | {
      progress?: number;
      requestId: number;
      stage: "quantizing-colors" | "tracing-boundaries" | "placing-stars";
      type: "progress";
    }
  | {
      placement: GuidedImagePlacementResult;
      requestId: number;
      revision: number;
      type: "placement";
    }
  | { error: string; requestId: number; type: "error" };
```

- 純粋なアルゴリズムは引き続き通常のTypeScript関数として単体テストし、Workerは薄い呼び出し層にする。
- マスクrevision、設定revision、requestIdの全てが最新の結果だけを表示する。
- スライダー操作中に発生した古い再配点は破棄する。
- Worker非対応時は同期フォールバックを許可するが、処理前後に描画機会を渡して状態表示を更新する。
- ダイアログを閉じたらWorkerをterminateし、転送済みバッファとImageBitmapを解放する。

### 11.2 キャッシュ

- マスクrevisionと画像が同じ間は `QuantizedSubjectMap` と内部境界線を再利用する。
- 配置モードまたは目標点数だけが変わった場合は、減色と境界抽出をやり直さず再配点だけを行う。
- 明色補正、画像由来星の種類、輪郭星の変更では点座標を再計算しない。
- 被写体指定が変わりマスクrevisionが更新された場合だけ、減色から再実行する。

## 14. テスト計画

### 14.1 単体テスト

- 単色画像はpalette 1色、内部境界0本になる。
- 左右2色画像は中央に1本の内部境界を作る。
- 3色同心円は2本の閉じた内部境界を作る。
- 8色を超える画像は使用ラベルが8以下になる。
- 微小な1〜2pxノイズ領域は境界にならない。
- 髪色相当の大領域と肌色相当の大領域は別ラベルとして残る。
- 内部境界は外形から指定距離だけ離れ、外形と重複しない。
- 境界色の交互割当が決定的である。
- 3モードで不要カテゴリが0点になる。
- 内部境界がない場合の余剰再配分が仕様どおりになる。
- 8、1024、2048点で安全半径0.94を超えない。
- 明色補正のオン／オフで点座標と境界本数が変わらない。

### 14.2 UIテスト

- 既定モードが `輪郭＋内部境界`、既定点数が1024である。
- スライダーの最大値が2048、刻みが8である。
- スライダーと数値入力が双方向同期する。
- モデルプロファイルは2操作、古典プロファイルは4操作を表示する。
- 非表示操作がフォーカス順に入らない。

### 14.3 統合テスト

## 15. 性能・品質ゲート

初期の目標値は次のとおりとし、Phase 0の基準計測で端末別に確定する。

| 項目 | 目標 |
| --- | --- |
| スライダー表示値の反映 | 1フレーム以内 |
| キャッシュ済み輪郭から2048点を再配点 | デスクトップ100ms以内、対象モバイル250ms以内 |
| 1024px画像の8色減色＋内部境界 | デスクトップ500ms以内、対象モバイル1500ms以内 |
| UIメインスレッド停止 | 50msを超えるlong taskなしを目標 |
| 連続10回の再配点 | Worker、ArrayBuffer、ImageBitmapの増加が収束 |
| 保存点数 | 指定値以下、候補十分時は指定値と一致 |

2048点は作品全体の描画負荷を増やすため、既存の最大粒子メーターによる警告を受ける。今回の機能内で黙って点数を削減せず、適用不能な全体上限がある場合は配置前に明示する。

## 16. リスクと対策

| リスク | 対策 |
| --- | --- |
| グラデーションが多数の偽境界になる | 8色制限、多数決、小領域統合、短線除外 |
| 髪の細いハイライトが消える | 細長い領域は面積だけで削除しない、境界長基準を併用 |
| 外形と内部境界が二重になる | 外形から2px相当を内部境界候補から除外 |
| 2048点でUIが停止する | 配置解析Worker、キャッシュ、デバウンス、revision破棄 |
| モデルの一時fast表示でタブがちらつく | 要求モードを優先し、恒久フォールバック時だけ切替 |
| 高視認色が最終星色と誤解される | 「仮表示」の凡例と説明を常時表示 |
| 既存作品の保存互換性が壊れる | 一時型だけ変更し、v4保存型は変更しない |
| 1024既定で既存端末の負荷が増える | 性能ゲート、Worker化、既存負荷メーター、2048実機検証 |
