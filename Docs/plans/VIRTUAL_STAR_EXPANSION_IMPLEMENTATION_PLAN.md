- 作成日: 2026-07-26
- ステータス: 計画
- 基準資料: [VIRTUAL_STAR_EXPANSION_RESEARCH.md](../VIRTUAL_STAR_EXPANSION_RESEARCH.md)
- 関連計画: [RENEWAL_IMPLEMENTATION_PLAN3.md](RENEWAL_IMPLEMENTATION_PLAN3.md)、[CRAFT_EDITOR_REFINE_IMPLEMENTATION_PLAN.md](CRAFT_EDITOR_REFINE_IMPLEMENTATION_PLAN.md)
- 対象: 仮想星データ、花火コンパイル、粒子挙動、湖面描画、打上結果プレビュー、編集画面の仮想星部品皿とバルーン

## 1. 目的と完了像

現行の仮想星は、色、寿命、落下、尾、ランダムな明るさ揺れを中心に表現している。本改修では、発光する時間、星ごとの位相、飛翔中の運動、終端効果を独立した属性として追加し、時差式イルミネーション、周期点滅、段階変色、光露、輝、葉落、ポッピングへ展開できる基盤を作る。

加えて、編集画面の仮想星バルーンを静的な抽象図から軽量なWebGLミニ花火へ置き換える。ユーザーが部品皿の仮想星を選ぶ前に、色変化、点滅周期、尾、落下、終端閃光、二次粒子が実際にはどのように見えるかを短いループで確認できるようにする。

完了時には次を満たす。

1. 仮想星に、決定論的な発光エンベロープ、段階変色、反復変色、終端閃光を設定できる。
2. レイヤー内の配置順、経度、緯度、半径、グループ、手動値から星ごとの発光位相を決定できる。
3. 葉落、遊泳、旋回と、終端スパーク／マイクロバーストを既存の弾道運動へ重ねられる。
4. 同じ作品、同じseed、同じ時刻なら、フレーム刻みに依存せず同じ色、明るさ、位相、運動オフセット、二次効果を得られる。
5. 最初の拡張として、基準資料で選定した9種類の内蔵仮想星を利用できる。
6. 仮想星バルーンはWebGLで短いミニ花火を再生し、選択した星の主要な見た目を本番と共通の評価関数で示す。
7. バルーン、編集画面の打上結果プレビュー、湖面確認で、表示密度と背景を除いた星の時間表現が一致する。
8. WebGLを利用できない環境、コンテキスト喪失、動きを減らす設定でも、星の内容と操作方法を失わない。
9. 既存のv2〜v4作品は読み込み・編集・保存でき、新しい効果を持たない星のコンパイル結果を変えない。
10. 実物の薬品、製造法、点火方法を扱わず、見た目と時間表現だけを編集対象にする。

本計画では、研究資料のPhase 1「発光基盤」とPhase 2「時差式」、およびWebGL仮想星バルーンを、最初のリリース単位として一続きに扱う。発光だけを先に公開して位相制御を後回しにすると、新作表現の中心であるイルミネーション、回転光環、波紋を構成できないためである。

## 2. 要求の解釈

### 2.1 バルーンで見せるもの

仮想星は一つの発光粒子の定義であり、それ自体は花火全体の配置形状を持たない。バルーンでは、選択した仮想星を決定的な少数点へ複製した「挙動確認用ミニ花火」を表示する。

- 通常、変色、点滅、光露、輝: 小さな球状開花で色、明暗、尾、消え際を見せる。
- リレー、グラデーション: 小さなリングへ代表的な経度位相を与え、光が流れることを見せる。
- 葉落、遊泳: 上向きに開いた扇状の初速から減速、横揺れ、落下を見せる。
- ポッピング: 少数の親星を飛ばし、終端で小粒へ分かれることを見せる。

このシナリオは、星の挙動を短時間で判別するための固定サンプルであり、編集中の花火玉全体の完成形ではない。バルーンには「挙動サンプル」と表示し、レイヤー配置を含む完成形は既存の打上結果プレビューと湖面確認で確認する。

### 2.2 「花火の挙動に近い」の範囲

バルーンが本番と共有するもの:

- 色段階と補間方式
- 発光エンベロープ、点滅周期、点灯率、位相
- 弾道、抗力、重力と追加の運動オフセット
- 尾の長さ、色、太さ
- 終端閃光、終端スパーク、マイクロバーストの発生時刻
- 固定seedによる決定性

バルーン専用に簡略化するもの:

- 星数と二次粒子数
- 初速とカメラ距離
- 背景、煙、湖面反射、打上筒、上昇中の玉
- 音声
- ポストプロセスのBloom。光のにじみは加算合成した点スプライトで近似する。

バルーンは本番の `NightSkyApp` や `FireworkSystem` をそのまま入れ子にしない。本番の評価関数と粒子更新則を共有しつつ、小さい表示面に必要な描画だけを持つ。

### 2.3 既存計画から変更する契約

`src/app/renewalContracts.ts` は現在、仮想星バルーンを `abstract-2d` / `abstract` と固定している。本改修では責務を次のように更新する。

| 表示 | 入力 | 描画 | 結果の責務 |
| --- | --- | --- | --- |
| 仮想星バルーン | 単一の仮想星＋固定サンプル配置 | `star-webgl`、失敗時は静的フォールバック | 本番評価関数を使う挙動サンプル |
| 打上結果プレビュー | 編集中の作品全体 | 現行SVG投影を維持しつつ共通評価関数を利用 | 固定seedの打上結果 |
| 湖面確認 | 単一作品 | `FireworkSystem` | 本番表示 |
| フリー鑑賞 | ショープラン | `FireworkSystem` | 本番表示 |

打上結果プレビューをWebGLへ全面置換することは本計画の必須範囲にしない。仮想星バルーンだけをWebGL化し、既存SVGプレビューは軌道投影の軽さとDOMテスト可能性を維持する。

## 3. 現状と解消する差分

| 領域 | 現在 | 本計画で解消する差分 |
| --- | --- | --- |
| 星データ | `VirtualStarPreset` の数値と `emissionKind` | 直交した `effectProfile` を任意追加 |
| 色 | `evaluateColorStages()` が常に滑らかに補間 | `smooth` / `step`、反復、往復、保持 |
| 点滅 | `FireworkSystem` が毎フレーム `Math.random()` で不透明度を変化 | 時刻とseedから決まる周期波形。従来の揺らぎも決定論化 |
| 位相 | レイヤー発火の小さな遅延のみ | 配置に基づく `effectPhase` を星ごとにコンパイル |
| 運動 | 抗力、重力、風による弾道 | 葉落、wander、spiralの決定論的オフセット |
| 二次効果 | 子花レイヤーによる24星の固定小球 | 親星単位の終端スパーク／少粒子分裂 |
| 尾 | 履歴線の長さと色。太さは点サイズ寄り | `trailWidth` の実効反映、効果による尾の明暗 |
| 煙 | 花火全体の開花煙 | 後期フェーズで星別 `smokeAmount` を反映 |
| コンパイラ | `CompiledStar` に位相と効果seedがない | 新効果を持つ星だけ任意メタデータを追加 |
| バルーン | `StarLibraryPanel` の静的SVG放射線 | WebGLミニ花火＋再生制御＋静的フォールバック |
| バルーン寿命 | `innerHTML` 再描画ごとにDOMを作り直す | エディター所有の単一レンダラーを再接続して使い回す |
| 打上結果プレビュー | 10時点の色と軌道をSVGアニメーション | 共通の色・発光評価を使用し、主要効果を反映 |
| 回帰契約 | バルーンは抽象2Dと固定 | 単一星だけ本番評価系へ変更 |

特に、現行エディターの `#render()` はワークスペース全体の `innerHTML` を置き換える。バルーンを開くたびに新しい `WebGLRenderer` を生成すると、再描画、Undo/Redo、選択変更のたびにコンテキストが増える。レンダラーをエディターのフィールドとして一つだけ所有し、DOM置換後は同じcanvasを新しいホストへ再接続する設計を必須とする。

## 4. データ設計

### 4.1 仮想星効果を直交した属性にする

`emissionKind` は部品皿の分類、既存音声、旧データ互換のため残す。新しい見た目は、次の任意フィールドを正本とする。

```ts
export interface VirtualStarEffectProfile {
  color?: {
    mode: "smooth" | "step";
    playback: "once" | "loop" | "pingPong";
    repeatCount?: number;
  };
  light?: {
    edgeSoftness?: number;
    frequencyHz?: number;
    mode: "continuous" | "strobe";
    phaseOffset?: number;
    dutyCycle?: number;
    terminal?: {
      duration: number;
      mode: "none" | "kouro" | "teka";
      sparkleCount?: number;
      strength: number;
    };
  };
  motion?: {
    amplitude?: number;
    frequencyHz?: number;
    mode: "ballistic" | "fallingLeaf" | "wander" | "spiral";
  };
  secondary?: {
    count?: number;
    mode: "none" | "spark" | "microBurst";
    speedScale?: number;
    triggerTime?: number;
  };
}
```

`light.mode` と `terminal` を分ける。これにより、点滅しながら最後に輝く星を列挙値の追加なしに表現できる。色、光、運動、二次効果の組合せを許容しつつ、各数値にはバリデーターとUIの安全範囲を設ける。

推奨範囲:

| 値 | 範囲 |
| --- | --- |
| `repeatCount` | 1〜8 |
| `frequencyHz` | 0.5〜18Hz |
| `dutyCycle` | 0.08〜0.92 |
| `edgeSoftness` | 0〜0.45 |
| `terminal.duration` | 正規化寿命の0.01〜0.2 |
| `terminal.strength` | 0〜3 |
| `motion.amplitude` | 0〜1 |
| `motion.frequencyHz` | 0.1〜8Hz |
| `secondary.count` | 0〜6。内蔵品質確認では最大6 |
| `secondary.triggerTime` | 正規化寿命の0.35〜1 |

未指定の `effectProfile` は、現在の連続発光、滑らかな色変化、弾道、二次効果なしへ解決する。

### 4.2 レイヤー位相

時差式は星だけでなく配置全体の属性である。v4編集意図の `LayerBaseV4` と実行用レイヤーの基底へ、任意の `effectTiming` を追加する。

```ts
export type EffectPhaseMapping =
  | "none"
  | "random"
  | "index"
  | "longitude"
  | "latitude"
  | "radius"
  | "group"
  | "manual";

export interface LayerEffectTiming {
  cycles: number;
  direction: "forward" | "reverse";
  mapping: EffectPhaseMapping;
  offset: number;
  spread: number;
}
```

- `none`: 全星を同期する。
- `random`: `assemblySeed`、レイヤーID、配置indexのhashから決定する。PRNGの消費順へ依存させない。
- `index`: `index / max(count - 1, 1)`。
- `longitude`: `atan2(z, x)` を0〜1へ正規化する。
- `latitude`: 正規化したY位置を0〜1へ写す。
- `radius`: 中心からの距離をレイヤー内の範囲で0〜1へ写す。
- `group`: 型物グループまたは安定した星グループ番号から決める。
- `manual`: `ManualLayerPoint.effectPhase?: number` を使用し、未指定点はindexへフォールバックする。

最終位相は方向、周期数、広がり、オフセットを適用して0以上1未満へ折り返し、`CompiledStar.effectPhase?: number` へ確定する。新効果がない既存星／既存レイヤーにはこのプロパティを出力せず、既存のコンパイルJSONを維持する。

`resolveLayerIntent()`、v3→v4変換、レイヤーの複製・追加、Undo/Redoで `effectTiming` を落とさないことを回帰テストにする。

### 4.3 保存形式と互換性

初回実装ではschema v5を導入せず、v4への任意フィールド追加として保存する。

- v2〜v4の既存フィールドは削除・改名しない。
- 既存作品へ新しい内蔵星や効果プロファイルを自動注入しない。
- 新しい作品と、新しい星を明示的に選んだ作品だけが新フィールドを保存する。
- バリデーターは新フィールドが存在するときだけ、列挙値、有限値、範囲、参照先を検証する。
- 読み込み時に不正な任意効果があれば作品全体を失うのではなく、その効果を安全な既定値へ正規化できる境界をデータローダー側に設ける。
- `legacyIntent` は引き続き比較用であり、実行時の効果正本にしない。

既存の `flicker` は真のストロボへ自動変換しない。「揺らぎ」という見た目を保ちつつ、時間と星seedから求める連続ノイズへ置き換え、バルーンと本番で同じ明るさになるようにする。ストロボは `effectProfile.light.mode === "strobe"` の新しい星だけで使用する。

## 5. 共通評価コア

### 5.1 純粋関数

Three.js、DOM、描画バッファへ依存しない評価モジュールを追加し、バルーン、SVGプレビュー、本番から使用する。

```ts
evaluateColorStages(stages, normalizedAge, profile): EvaluatedColor
evaluateLightEnvelope(profile, normalizedAge, effectPhase, effectSeed): number
evaluateMotionOffset(profile, ageSeconds, effectPhase, effectSeed): Vector3Value
evaluateSecondaryEvent(
  profile,
  previousNormalizedAge,
  normalizedAge,
  effectSeed,
): SecondaryEvent | undefined
evaluateVirtualStarAppearance(input): EvaluatedVirtualStarAppearance
```

`evaluateVirtualStarAppearance()` は、色、発光倍率、尾の色／発光倍率、運動オフセット、終端状態を一度に返す。バルーンと本番が個別に式を組み立てないようにする。

### 5.2 決定性

- 点滅は `sin`、矩形波、`smoothstep` を時刻から評価し、フレーム数を数えない。
- 従来の揺らぎは星seedと量子化時間をhashし、必要なら隣接値を補間する。
- 運動は絶対時刻からオフセットを求め、前フレームの乱数を蓄積しない。
- 二次効果は `previousAge < triggerTime && currentAge >= triggerTime` の境界横断で一度だけ発生させる。
- 二次粒子の方向、速度、色は親の `effectSeed` と子indexから決定する。
- `deltaSeconds` が1/30、1/60、可変刻みでも、同じ絶対時刻の評価値が許容誤差内で一致する。

### 5.3 実行時の保持値

新効果を使う実行時星だけ、次を保持する。

- `effectProfile`
- `effectPhase`
- `effectSeed`
- `previousNormalizedAge`
- `secondaryTriggered`

`CompiledStar` の `effectSeed` は、作品の `assemblySeed`、レイヤーID、星ID、配置indexからhashする。湖面表示と編集プレビューが異なる起動seedを使っても、保存された星の位相構造は維持し、起動ごとの差は既存の小さな発射ばらつきだけに限定する。

## 6. WebGL仮想星バルーン

### 6.1 描画構成

`src/render/preview/StarBehaviorPreviewRenderer.ts` を新設し、次の小さいThree.jsシーンを所有する。

- 透明背景の `Scene`
- 正面比較を安定させる `OrthographicCamera`
- 加算合成する円形点スプライト
- 親星の短い履歴から作る尾バッファ
- 二次粒子用の共有点バッファ
- 固定seedで生成する挙動別のプレビューシナリオ

`EffectComposer`、`UnrealBloomPass`、夜景、湖面、音声は使用しない。点スプライトのシェーダーで中心を白く、外周を透明にし、加算合成で小さい画面でも輝度差を読めるようにする。

### 6.2 プレビューシナリオ

`src/render/preview/buildStarBehaviorPreviewScenario.ts` を純粋関数として追加する。入力は仮想星定義と固定seed、出力は初期位置、初速、位相、寿命、二次効果上限を持つ軽量計画とする。

| 星の主効果 | 配置 | 位相 |
| --- | --- | --- |
| continuous / step / terminal | 28点のFibonacci球 | 同期 |
| strobe | 28点のFibonacci球 | 同期。色と点灯／消灯を優先 |
| relay / gradient推奨星 | 32点のリング | longitude |
| fallingLeaf / wander / spiral | 18点の上向き扇 | indexを少量ずらす |
| spark / microBurst | 12点の疎な球 | 同期。子粒子を見やすくする |

プレビューは上昇中の玉を省き、開花直前0.15秒の暗転から始める。ループ長は `burnDuration + terminal/secondary余韻` を基に1.8〜5.8秒へクランプする。

### 6.3 UI

現行バルーンのオーバーレイ、画面内クランプ、外側クリック、Escape、長押し、フォーカス復帰を維持する。

変更後の内容:

- 見出し: 仮想星名
- WebGL表示面: `data-star-behavior-preview`
- 効果タグ: 例「段階変色」「6Hz点滅」「経度リレー」「輝」「葉落」
- 色段階の一覧
- 注記: 「挙動サンプル。完成形は打上結果プレビューで確認」
- 操作: 再生／一時停止、最初から、閉じる

canvas単体へ意味を持たせず、ラッパーへ星名と主要効果を含む `role="img"` / `aria-label` を付ける。効果タグと色段階はcanvasを見られない場合もDOMテキストで読めるようにする。

`prefers-reduced-motion: reduce` の場合は自動再生せず、代表時刻の静止状態を表示する。ユーザーが「再生」を押した場合だけ一周再生し、自動ループしない。

### 6.4 ライフサイクル

`IntegratedCraftEditor` が `StarBehaviorPreviewRenderer` を一つだけ所有する。

1. 初回のバルーン表示時に遅延生成する。
2. `#render()` 後、新しい `[data-star-behavior-preview-host]` へ同じcanvasを再接続する。
3. 星IDまたは効果定義の署名が変わったときだけシナリオとGPUバッファを更新する。
4. バルーンを閉じたらRAFを停止するが、エディターが開いている間はレンダラーを再利用する。
5. `document.hidden`、バルーンが画面外、幅または高さが0のときは更新を停止する。
6. `ResizeObserver` でバルーンの実寸へ追従する。
7. エディター破棄時に、RAF、Observer、geometry、material、renderer、canvasを破棄する。

WebGLコンテキストはエディターにつき最大1個とする。DOM再描画のたびに生成しない。

### 6.5 性能上限

- canvasのCSS表示は現行バルーン内の約216×116pxを基準とする。
- ピクセル比は `min(devicePixelRatio, 1.5)`。
- 親星48以下。
- 表示中の二次粒子192以下。
- 尾頂点4,096以下。
- 描画は最大30fps。時刻評価は実時間を使うため挙動速度は変えない。
- フレーム更新中の配列生成、`Color` の大量生成、geometry再作成を避ける。
- WebGLプレビューは花火本番の `MAX_STARS`、煙、反射バッファを共有しない。

### 6.6 フォールバック

次の場合はWebGL表示面を静的フォールバックへ切り替える。

- `WebGLRenderer` の生成失敗
- `webglcontextlost`
- 端末またはブラウザーの制約で描画が継続できない

フォールバックは、共通評価関数で代表時刻の色と明るさを求めたSVGまたはDOM図を表示する。現在の放射線図をそのまま「実挙動」と表示せず、「簡易表示」のラベルと効果タグを併記する。コンテキスト復帰時の自動再生成は初回範囲に含めず、バルーンを閉じて開き直したときに一度だけ再試行する。

## 7. 本番描画と打上結果プレビュー

### 7.1 `FireworkSystem`

- `Math.random()` によるフレーム依存の点滅を共通評価関数へ置き換える。
- 点の位置は弾道位置に `evaluateMotionOffset()` を加えた描画位置を使う。
- 尾の履歴にも同じ描画位置を記録し、葉落や遊泳の軌跡が尾へ反映されるようにする。
- 点のalphaへ色段階強度、発光エンベロープ、輝度を順に適用する。
- 尾は本体と別の発光倍率を使用できるようにする。
- 二次イベント発生時は、上限を確認して親星の位置と速度から小粒子を生成する。
- `trailWidth` を点サイズだけでなく線描画へ反映する方式は後期フェーズで導入する。

### 7.2 `CompiledBurstPreviewRenderer`

現行の決定的なレイヤー別サンプリングと軌道投影を維持し、軌道点を作る際に共通評価関数を利用する。

- `PreviewTrajectoryPoint` に発光倍率と、必要なら終端／二次効果の要約を追加する。
- 10フレーム固定では高周波点滅を表せないため、点滅星を含む場合だけ時系列サンプルを周期から導出し、最大48点へ制限する。
- SVGアニメーションで表現できない粒状尾や二次粒子は、初回は要約表示にとどめ、完成形はWebGLバルーンと湖面確認へ委ねる。
- プレビューの固定seedと湖面確認のseedが異なっても、同じ時刻における星効果の式は一致させる。

### 7.3 負荷見積り

`estimateBurstCost()` に次を追加する。

- `secondaryParticleCount`
- `terminalSparkCount`
- `effectTrailVertexEstimate`
- `smokeEmitterEstimate`（星別煙を導入するフェーズ）

上限判定では、親星だけでなく同時存在し得る二次粒子を `maximumParticles` に含める。遠距離または高負荷時は、次の順に簡略化する。

1. 終端スパークの粒数を減らす。
2. マイクロバーストを点スプライトの一時的な拡大へ置き換える。
3. 星別煙をサンプリングする。
4. 尾の履歴点数を減らす。

発光位相、色、終端時刻はLODで変えない。

## 11. 実装フェーズ

### Phase 0: 契約と回帰基準

1. 既存8星、14花火、v2〜v4fixtureのコンパイル結果と目視基準を記録する。
2. バルーンの責務を「抽象2D」から「本番評価関数によるWebGL挙動サンプル」へ更新する。
3. 新旧データの互換条件と、負荷上限を受け入れ契約として追加する。
4. WebGLバルーンのデスクトップ／モバイル寸法とフォールバック状態の基準画像を用意する。

完了条件:

- 新効果を持たない既存作品について、意図しないコンパイル差分がないことを検出できる。
- バルーン、打上結果プレビュー、湖面確認の責務がテストで区別される。

### Phase 1: データと共通評価コア

1. 任意の `effectProfile` と `effectTiming` を型、validator、v4解決経路へ追加する。
2. 色、発光、運動、二次効果の純粋評価関数を実装する。
3. `CompiledStar` へ任意の `effectPhase` / `effectSeed` を追加する。
4. 従来の `flicker` を決定論的な揺らぎとして共通評価へ移す。
5. フレーム刻み、境界時刻、seed、旧データ互換の単体テストを追加する。

完了条件:

- 同じ絶対時刻の評価値が1/30秒、1/60秒、可変刻みで一致する。
- `step` 境界の前後で色が補間されない。
- 光露と輝の発生区間、最大強度、終端後の消灯が区別される。
- 既存効果なしの星ではコンパイルJSONに新しい任意プロパティが出ない。

### Phase 2: P0発光表現とWebGLバルーン

1. `FireworkSystem` と `CompiledBurstPreviewRenderer` を共通評価へ接続する。
2. 強白点滅、彩色パステル点滅、銀光露、白銀輝、紅青反復変化を追加する。
3. 固定シナリオ生成と `StarBehaviorPreviewRenderer` を実装する。
4. バルーンへWebGL表示面、再生／一時停止、最初から、効果タグを追加する。
5. renderer再利用、ResizeObserver、非表示時停止、破棄、WebGL失敗時フォールバックを実装する。

完了条件:

- バルーンと湖面確認の指定時刻で、同じ星の色、発光倍率、終端状態が一致する。
- 点滅の点灯と消灯が目視で明確に区別できる。
- 光露は余韻、輝は強い一瞬の終止として見分けられる。
- バルーンを50回開閉してもWebGLコンテキストとRAFが増え続けない。
- 390×844でもバルーン全体と再生操作が画面内に収まる。

### Phase 3: 時差式と初回リリース

1. index、longitude、latitude、radius、random、group、manualの位相マッピングを実装する。
2. 選択レイヤーインスペクターへ「光る順番」を追加する。
3. 時差リレー星、流光グラデーション星を追加する。
4. 彩色イルミネーション、回転光環、光の波紋、光露変化菊を追加する。
5. バルーンではリレー系の代表リングを再生し、打上結果プレビューでは実レイヤーの位相を表示する。

完了条件:

- 経度位相でリング上の点灯が一方向へ進む。
- 半径位相で中心から外、逆方向指定で外から中心へ進む。
- 同じ設計とseedで、位相順が再コンパイル後も一致する。
- 星の位置そのものを不自然に回さず、発光順だけで回転して見える。

Phase 0〜3を最初の公開単位とする。Phase 2終了時点では開発環境で統合確認し、時差式まで揃ってから一般利用へ出す。

### Phase 4: 運動と二次効果

1. fallingLeaf、wander、spiralの運動オフセットを本番とバルーンへ追加する。
2. 終端スパークとマイクロバーストを実装する。
3. 点滅葉落星、はじけ子花星を追加する。
4. 色づく黄葉、春雪・夏雪、ポッピングシャワーを追加する。
5. 二次粒子を負荷見積りとLODへ統合する。
6. 必要に応じて終端音を追加し、ユーザー操作なしのバルーンでは音を鳴らさない。

完了条件:

- 葉落が柳の単純な垂下と異なり、減速と横揺れで識別できる。
- ポッピングが千輪の子花と異なり、親星の終端で少粒子へ分かれる。
- 二次イベントが大きいdeltaでも欠落せず、同じ親から二重発生しない。
- 最大粒子見積りが二次粒子を含む。

### Phase 5: 編集と精密化

1. 星効果の詳細エディターを追加する。
2. 星単位の煙、尾の実効線幅、粒状尾、尾だけの点滅を実装する。
3. ストップモーションプリセットと手動位相編集を仕上げる。
4. 動画参照による新作花火との目視比較を行う。
5. 観客距離、画面解像度、端末性能に応じたLODを調整する。

完了条件:

- 星を複製して色と効果を変更し、Undo/Redo、保存、再読込後も同じ見た目になる。
- 部品皿、打上結果プレビュー、湖面確認の差が、定義済みの簡略化範囲内に収まる。

## 14. リスクと対策

| リスク | 対策 |
| --- | --- |
| 効果の組合せで型とUIが爆発する | `emissionKind` を増やさず、色・光・運動・二次効果を直交させる |
| 旧作品の見た目が変わる | 新フィールドを任意にし、既存星は連続発光へ解決。旧揺らぎは振幅と平均輝度を保つ |
| バルーンと本番が再び乖離する | 時間評価を純粋関数へ集約し、描画層に独自の効果式を持たせない |
| `innerHTML` 再描画でWebGL資源が漏れる | エディターごとにレンダラー1個、canvas再接続、明示的な停止・破棄 |
| 小さいバルーンで花火が潰れる | 正投影、固定シナリオ、加算点スプライト、挙動別の星数と初速 |
| 高周波点滅がSVGプレビューで欠落する | 周期由来の可変サンプル。正確な短周期確認はWebGLバルーンと湖面へ集約 |
| ポッピングで粒子数が急増する | 親1個につき2〜6粒、同時数上限、見積り、LOD |
| WebGLを使えない端末がある | 効果タグと代表時刻の静的フォールバックを常備 |
| 自動再生が負担になる | 非表示時停止、30fps上限、reduced motionでは明示再生のみ |
| 実在作品の再現と誤解される | 「挙動サンプル」と明記し、競技作品の正確な再現をうたわない |

着手順は次とする。

```text
互換契約
  -> 共通の時間評価
  -> 本番描画への接続
  -> WebGL仮想星バルーン
  -> 配置位相
  -> P0/P1内蔵星
  -> 新作系花火プリセット
  -> 運動・二次効果・精密化
```

WebGLバルーンを共通評価コアより先に独立実装しない。先に見た目だけを作ると、本番との式の二重管理が残るためである。また、Phase 0〜3を初回公開単位とし、点滅・変色・終端表現・時差式・WebGLプレビューが揃った状態で受け入れ確認を行う。
