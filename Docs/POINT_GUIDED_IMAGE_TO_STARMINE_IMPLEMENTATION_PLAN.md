# 点指定式「画像から仮想星配置」機能 実装計画書

- 作成日: 2026-07-17
- ステータス: 計画
- 対象: 玉内配置ワークベンチの手動レイヤー
- 基準実装: [IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md](IMAGE_TO_STARMINE_IMPLEMENTATION_PLAN.md)
- 技術調査: [IMAGE_TO_VIRTUAL_STARS_BROWSER_RESEARCH.md](IMAGE_TO_VIRTUAL_STARS_BROWSER_RESEARCH.md)

## 1. 目的

現在の「画像から生成」は、画像外周から背景を推定し、被写体のマスク境界と内部エッジを最大240個の仮想星へ変換している。この方式は単純背景には軽くて速い一方、複雑な背景、複数被写体、被写体と背景が同系色の画像では、ユーザーが意図する被写体と重要な特徴を自動判定できない。

本計画では、画像選択後に確認ダイアログを開き、ユーザーが次の点を指定できるようにする。

1. **被写体点**: 残したい被写体の内側。マスク生成の前景プロンプトに使う。
2. **背景除外点**: 被写体から除きたい場所。マスク生成の背景プロンプトに使う。
3. **特徴点**: 目、口、耳、ロゴなど、打上後も残したい特徴。マスクではなく仮想星の配点へ使う。

完了状態は次のとおり。

- 画像を選ぶと、作品を変更する前に点指定ダイアログが開く。
- 被写体点を最低1点指定すると、ブラウザ内で被写体マスクと仮想星プレビューが生成される。
- 背景除外点と特徴点を追加・削除すると、プレビューだけが更新される。
- 「配置」を確定したときだけ、現在の切断面へ通常の `ManualLayerPoint` として反映される。
- 生成全体はUndo 1回で戻り、画像、マスク、指定点は保存データへ含めない。
- 画像は外部APIへ送信しない。モデル推論を使う場合もブラウザ内だけで実行する。

## 2. 設計上の決定

### 2.1 点を用途別に分離する

| 点種別 | 必須 | 上限 | マスク生成へ渡す | 仮想星配点へ使う | 表示 |
| --- | --- | --- | --- | --- | --- |
| 被写体点 | 1点 | 3点 | 前景ラベル `1` | 対象成分の保持 | `＋` と「被写体」 |
| 背景除外点 | 任意 | 5点 | 背景ラベル `0` | 使わない | `−` と「背景」 |
| 特徴点 | 任意 | 5点 | 渡さない | 周辺へ優先配点 | `★` と「特徴」 |

特徴点を前景プロンプトへ混ぜない。目や口を追加しただけで被写体マスクの形が大きく変わることを防ぎ、マスク修正と花火としての強調を独立して調整できるようにする。

### 2.2 高精度マスクは任意モデルとして導入する

第一候補は `@huggingface/transformers` と `Xenova/slimsam-77-uniform` を使う点プロンプト式セグメンテーションとする。

- 画像エンコーダーは画像ごとに1回だけ実行する。
- 被写体点／背景除外点を変更したときは、プロンプトエンコーダーとマスクデコーダーだけを再実行する。
- WebGPUを機能検出し、利用できる場合はWebGPU、利用できなければWASMを使う。
- モデルとWASMは自己ホストし、モデルIDとファイルハッシュを固定する。
- 重みをGitへ直接置くか、Git LFSまたはビルド時のハッシュ検証つき取得にするかはPhase 0で決める。いずれの場合も実行時は同一オリジンから配信する。
- 画像ファイルや画素はモデル配布元へ送らない。
- モデル取得、初期化、推論はWorker内で行う。

Phase 0のPoCで、対象ブラウザ、端末性能、モデル資産、ライセンス、マスク品質を検証する。SlimSAMが合格基準を満たさない場合は、同じ `PromptMaskProvider` 契約の実装をMediaPipe Interactive SegmenterまたはGrabCutへ交換する。UI、特徴点配分、保存形式は変更しない。

### 2.3 現行方式をフォールバックとして残す

- 透過PNGはアルファを優先する。
- モデルをまだ取得していない間は、現行の外周色・洪水充填マスクを仮プレビューに使う。
- モデルの初期化失敗、メモリ不足、非対応ブラウザでは現行方式へ戻し、特徴点だけを反映できるようにする。
- フォールバックしたことは通知するが、画像生成操作自体は失敗させない。

### 2.4 保存schemaを変更しない

指定点、元画像、ImageBitmap、モデル埋め込み、マスクは一時セッションデータである。確定後は現在と同じ `ImagePlacementResult` を `applyImagePlacementToDraft()` へ渡し、保存するのは `ManualLayerPoint` の `id`、`position`、`section`、`starId` だけとする。

`FireworkDesignV4`、マイグレーション、保存バリデーターは変更しない。

## 3. ユーザー体験

### 3.1 操作フロー

```text
手動レイヤーで「画像から生成」
  → ファイル選択
  → 点指定ダイアログ
       画像デコード
       高速な仮マスクを表示
  → 「被写体」モードで残したいものを1点タップ
       必要ならモデル取得・初期化
       被写体マスクと仮想星プレビューを更新
  → 必要に応じて
       「背景を除外」で誤検出箇所をタップ
       「特徴を強調」で目・口・ロゴ等をタップ
  → 目標点数と置換／追加を確認
  → 「配置」
       現在の切断面へ1回のupdateIntentで反映
```

### 3.2 点指定ダイアログ

ダイアログは `role="dialog"`、`aria-modal="true"` を持つ。既存の棚ダイアログと同じく背景を操作不能にし、フォーカストラップ、Escapeでの取消、閉じた後の「画像から生成」ボタンへのフォーカス復帰を実装する。

構成は次のとおり。

| 領域 | 内容 |
| --- | --- |
| ヘッダー | 「画像から仮想星を作る」、処理状態、閉じる |
| 中央 | 元画像、半透明マスク、仮想星候補、指定点を重ねたキャンバス |
| 点モード | `被写体`、`特徴`、`背景を除外`。既定は被写体 |
| 操作 | 1つ戻す、選択点を削除、点をすべて消す、拡大、縮小、全体表示 |
| 設定 | 目標点数8〜240、生成方法（置換／追加） |
| フッター | 取消、配置 |

表示記号は色だけに依存させない。

- 被写体点: 丸囲みの `＋`
- 背景除外点: 丸囲みの `−`
- 特徴点: 丸囲みの `★`

各点は連番と読み上げ名を持ち、ダイアログ内の点一覧から削除できる。キャンバスはキーボードフォーカスを受け取り、矢印キーで照準を移動し、Enter/Spaceで現在モードの点を追加できるようにする。モバイルでは画像を画面幅へ収め、拡大中はパンしても点の正規化座標が変化しないようにする。

### 3.3 非同期状態

```text
idle
  → decoding
  → awaiting-subject
  → loading-model
  → encoding-image
  → segmenting
  → ready
  → applying
  → closed

任意状態 → error（再試行、軽量方式で続行、取消）
```

- 被写体点が0件の間は「配置」を無効にする。
- モデル取得中も点の追加・削除は許可し、最新状態だけを推論する。
- 推論中に点が変わった場合は古い結果を破棄し、最後のrevisionを再実行する。
- ダイアログを閉じた後に完了した結果は適用しない。
- レイヤー削除、ロック、画面遷移が起きた場合は確定時に再検証する。

## 4. データ契約

新規の一時データ型を `GuidedImagePlacementTypes.ts` に定義する。

```ts
export type ImagePromptKind = "subject" | "background" | "feature";

export interface NormalizedImagePoint {
  x: number; // 0...1、元画像の左から右
  y: number; // 0...1、元画像の上から下
}

export interface ImagePrompt {
  id: string;
  kind: ImagePromptKind;
  point: NormalizedImagePoint;
}

export interface GuidedImagePlacementSettings {
  featureBudgetRatio: number;
  targetCount: number;
}

export interface SubjectMask {
  data: Uint8Array; // 0 or 255
  height: number;
  width: number;
}

export interface GuidedPlacementDiagnostics {
  featurePointCounts: Record<string, number>;
  maskProvider: "alpha" | "fast" | "slimsam" | "fallback";
  maskRevision: number;
  outlinePointCount: number;
  totalPointCount: number;
}
```

点は元画像基準の正規化座標で保持する。表示キャンバスのCSSサイズ、devicePixelRatio、ズーム、パン、モデル入力解像度、解析マスク解像度へ依存させない。

### 4.1 Workerプロトコル

```ts
type ImageWorkerRequest =
  | { type: "initialize"; requestId: number }
  | { type: "set-image"; requestId: number; image: ImageBitmap }
  | {
      type: "segment";
      requestId: number;
      revision: number;
      prompts: ImagePrompt[];
    }
  | { type: "cancel"; requestId: number }
  | { type: "dispose" };

type ImageWorkerResponse =
  | { type: "progress"; requestId: number; stage: string; progress?: number }
  | { type: "mask"; requestId: number; revision: number; mask: SubjectMask }
  | { type: "error"; requestId: number; code: string; recoverable: boolean };
```

`AbortSignal`の転送には依存せず、`requestId` と `revision` で古い処理を無効化する。ImageBitmap、マスクのArrayBufferはtransferableとして受け渡し、不要になったImageBitmap、Tensor、GPUBufferは明示的に破棄する。

## 5. 画像処理パイプライン

### 5.1 デコードと前処理

1. ファイル容量は現行どおり20MB以下。
2. デコード後の総画素数にも上限を設ける。初期値は24メガピクセルとする。
3. `createImageBitmap()` でEXIFの向きを反映したImageBitmapを作る。
4. ダイアログ表示用とモデル入力用は元のImageBitmapから生成する。
5. 点群解析用マスクは最長辺512pxを上限とする。現行の高速方式は256pxのままでもよい。
6. 画像の縦横と向きが確定した後で、画面座標と正規化座標を変換する。

### 5.2 点プロンプトによるマスク生成

- `subject` をラベル1、`background` をラベル0としてモデルへ渡す。
- `feature` はモデルへ渡さない。
- 画像埋め込みは `set-image` ごとに1回だけ生成・保持する。
- モデルが複数マスクを返した場合、予測IoUだけで決めず、次の制約を満たす候補を優先する。
  - すべての被写体点がマスク内にある。
  - 背景除外点がマスク外にある。
  - 面積が画像全体の1〜95%に収まる。
  - 同点なら予測IoUが高い。
- 制約を満たすマスクがない場合は、最も違反が少ない候補を表示し、追加点を促す。

### 5.3 マスク整形

1. 確率マスクを二値化する。
2. 1〜2px相当のOpeningで孤立ノイズを除く。
3. Closingで小さな切れ目を閉じる。
4. 被写体点を含む連結成分は必ず保持する。
5. 背景除外点を含む小成分は除く。
6. 穴と内側輪郭は階層情報として残す。
7. 被写体外接矩形と重心を診断結果へ含める。

形態学処理は決定的な純粋関数として実装し、モデル出力とは別に単体テストする。

### 5.4 順序付き輪郭と弧長配点

現行の境界画素集合を画像走査順に間引く方式を、順序付き輪郭へ変更する。

1. Marching Squaresまたは同等の輪郭追跡で、閉じた輪郭列と穴の階層を得る。
2. 1px程度のジグザグを簡略化するが、耳、指、ロゴ角などの大きな屈曲は残す。
3. 輪郭ごとの周長と役割（外形／穴／内側）を求める。
4. 外形予算を加重周長で分配する。
5. 各輪郭の累積弧長に沿って等間隔に再サンプリングする。
6. 小さな正当成分へ最低点数を保証し、背景ノイズには点を割り当てない。

画像全体ではなく採用マスクの外接矩形を中心へ移し、アスペクト比を保って `IMAGE_PLACEMENT_SAFETY_RADIUS = 0.94` の円へ収める。これにより、余白や画像内の偏りが仮想星の利用可能領域を消費しない。

### 5.5 特徴点への優先配点

既定の配点は次のとおり。

```text
特徴予算の下限 = featureCount
特徴予算の希望値 = min(floor(targetCount × 0.25), featureCount × 16)
特徴予算 = min(floor(targetCount × 0.40), max(下限, 希望値))
外形予算 = targetCount - 特徴予算
```

- 特徴点が0件なら全点を外形へ使う。
- 各特徴を最低1点で示せるよう、特徴追加時に `targetCount < ceil(featureCount / 0.40)` なら目標点数を必要最小値まで引き上げて通知する。
- 特徴予算が `特徴数 × 8` 以上ある場合は、各特徴へ最低8点、最大16点を割り当てる。
- 目標点数が少なく最低8点を保証できない場合は、特徴間で均等に減らし、各特徴の中心を最低1点で示す。外形は常に最低60%残す。
- 特徴点の周囲を画像短辺の4〜8%の半径で解析する。
- 周辺のRGB Sobelエッジを線として追跡し、強い連続線へ弧長配点する。
- エッジがない場合は、特徴位置を中心とした小さな4〜8点の輪または短い印として表現する。
- 複数特徴の範囲が重なる場合は統合し、同じ点を重複生成しない。
- 特徴点がマスク外にある場合は配置せず、その点を警告表示する。

特徴点から生成した星色は、その周囲の前景画素の中央値または主要色を使う。外形色は現行どおり被写体マスク全体の代表色1色とし、`resolveImageStars()` で既存の仮想星へ割り当てる。初回実装では星定義、最大4色、画像由来星を作らない方針を変更しない。

### 5.6 点数不足と余りの処理

- 外形と特徴で目標数に届かない場合は、外形輪郭の間隔を狭めて補う。
- それでも8点未満なら生成失敗とする。
- 目標数を超えた場合は、外形、特徴のそれぞれで弧長順を保って決定的に間引く。
- すべての点が安全半径0.94以内にあることを最終検証する。
- 同じ画像、同じ指定点、同じ設定、同じプロバイダからは同じ順序の点群を返す。

## 6. エディター統合

### 6.1 既存操作との関係

- 「画像から生成」ボタンとファイルinputは維持する。
- ファイル選択後、現在の `#applyImagePlacement()` で即時適用せず、`GuidedImagePlacementDialog` を開く。
- ダイアログ開始時に、対象 `layerId`、切断面 `section`、生成方法、目標点数をスナップショットする。
- 確定時に対象レイヤーの存在、`authoringMode === "manual"`、`locked === false` を再確認する。
- 成功時だけ `updateIntent("画像から配置")` を1回呼び、`applyImagePlacementToDraft()` を使う。
- 取消、デコード失敗、モデル失敗、点不足ではdraftを変更しない。
- 確定後の点は従来どおり移動、削除、星置換、Undo/Redoできる。

### 6.2 ダイアログの所有権

`IntegratedCraftEditor` に画像処理の細かな状態を増やさず、`GuidedImagePlacementDialog` が一時セッション、Worker、Blob URL、フォーカスを所有する。

```ts
interface GuidedImagePlacementDialogResult {
  placement: ImagePlacementResult;
  settings: {
    applyMode: "append" | "replace";
    targetCount: number;
  };
}

openGuidedImagePlacementDialog(file, options): Promise<
  GuidedImagePlacementDialogResult | undefined
>;
```

`undefined` は取消を表す。エディターは結果だけを受け取り、現在の切断面へ適用する。

## 8. 実装フェーズ

### Phase 0: モデルPoCと採否ゲート

1. SlimSAMをWorker内で動かし、正点／負点からマスクを生成する最小PoCを作る。
2. WebGPUとWASMで、画像エンコード1回、プロンプト再推論、メモリ解放を確認する。
3. `latte.png`、`mao.png` と難易度別10枚以上で、1〜3個の被写体点と0〜3個の背景点を試す。
4. Chrome、Safari、Firefoxの対象版と、デスクトップ、対象モバイルで動作確認する。
5. 実際に配るモデルファイルだけの容量、ライセンス文、Git/LFS/ビルド取得のいずれを使うかを確定する。

採用基準:

- キャッシュ後の処理がデスクトップ2秒以内、対象モバイル5秒以内。
- 難しい画像の80%以上を、被写体／背景の合計3点以内で意図したマスクへ修正できる。
- Worker終了または明示破棄で、次回生成に影響するメモリ増加が残らない。
- WebGPU非対応時にWASMまたは高速方式へ復帰できる。
- モデルとライブラリの配布条件がプロジェクト方針に適合する。

不合格の場合は `PromptMaskProvider` をMediaPipe Interactive Segmenterで再評価し、それでも不合格ならGrabCut＋前景／背景点を正式経路とする。

### Phase 1: 純粋ロジックと契約

1. 点、マスク、Workerメッセージの型を追加する。
2. `ImagePromptSession` の純粋な状態遷移を実装する。
3. 現行 `ImagePlacementRecipe` から高速マスク生成とマスク→点群変換を分ける。
4. マスク整形、輪郭追跡、外接矩形正規化、弧長配点を実装する。
5. 特徴点の局所エッジ追跡と予算配分を実装する。

完了条件:

- 合成マスクから輪郭順と弧長間隔が決定的に得られる。
- 0〜5個の特徴点で総点数と外形60%以上を守る。
- 既存の画像生成テストが結果契約を維持して成功する。

### Phase 2: 点指定ダイアログ

1. 画像、マスク、星候補、点を重ねるダイアログを実装する。
2. 被写体／特徴／背景モード、点一覧、削除、Undo、ズーム、パンを実装する。
3. 正規化画像座標と表示座標の相互変換を実装する。
4. フォーカストラップ、Escape、キーボード照準、live regionを実装する。
5. 390×844を含むモバイルレイアウトへ対応する。

完了条件:

- CSS表示サイズ、ズーム、devicePixelRatioが変わっても同じ画像点を指す。
- 被写体点0件では配置できず、各点種別の上限を超えない。
- マウス、タッチ、キーボードの各経路で点を追加・削除できる。

### Phase 3: Workerと点プロンプト推論

1. `ImageSegmentationClient` とWorkerプロトコルを実装する。
2. モデルを動的に初期化し、画像埋め込みを再利用する。
3. 正点／負点から候補マスクを生成・採点する。
4. 進捗、再試行、requestId/revision、取消、破棄を実装する。
5. WebGPU→WASM→高速方式のフォールバックを実装する。

完了条件:

- 連続して点を打っても最後のrevisionだけが表示される。
- ダイアログを閉じた後にWorker結果がDOMやdraftを変更しない。
- 2枚目の画像へ1枚目の埋め込みやマスクが混入しない。

### Phase 4: エディター適用

1. `IntegratedCraftEditor` のファイル選択をダイアログ起動へ接続する。
2. 確定結果を既存の `applyImagePlacementToDraft()` へ渡す。
3. 置換／追加、現在断面、対象レイヤー、ロックを確定時に再検証する。
4. 成功通知、フォーカス復帰、Undo/Redoを接続する。

完了条件:

- 取消時とエラー時にdraftが完全一致で不変。
- 確定はUndo 1回、Redo 1回で往復できる。
- schema v4、星ライブラリ、画像非保存を維持する。

### Phase 5: 性能、セキュリティ、実ブラウザQA

1. デコード総画素上限、モデル資産の自己ホスト、CSP、キャッシュを確認する。
2. コールド取得、ウォーム推論、プロンプト再推論、点群化を個別計測する。
3. Tensor、ImageBitmap、Object URL、Workerの解放を確認する。
4. 対象ブラウザと画面寸法で操作、コンソール、ネットワークを確認する。
5. `lint`、全テスト、format check、production buildを通す。

完了条件:

- 画像データの外部通信が0件。
- 通常の画像生成を使わない起動では、モデルコード・重みを取得しない。
- ダイアログ操作中に50ms超のメインスレッドLong Taskを発生させない。
- 既存の制作、保存、湖面確認、フリー鑑賞に回帰がない。

## 9. テスト計画

### 9.1 単体テスト

| 対象 | 内容 |
| --- | --- |
| `ImagePromptSession` | 点種別、上限、追加順、削除、Undo、revision、リセット |
| 座標変換 | 縦横比、余白、ズーム、パン、devicePixelRatio、画像端 |
| マスク整形 | Opening/Closing、正点成分保持、負点成分除外、穴の保持 |
| 輪郭追跡 | 円、矩形、穴、複数成分、細線、画像端、順序の決定性 |
| 弧長配点 | 等間隔、総数、成分別最低点、外形予算、点不足の補完 |
| 特徴配点 | 0〜5点、十分な予算時の各特徴最低8点、少数予算時の均等縮退、範囲重複、マスク外、エッジなし |
| マスク候補選択 | 正点内包、負点除外、面積制約、IoU同点、候補なし |
| 色割当 | 外形代表色、特徴局所色、既存星のみ、最大4色 |

### 9.2 Worker／クライアントテスト

モデル本体は単体テストでロードせず、Worker応答を偽装する。

- 初期化→画像→推論→結果の順序。
- 古いrequestIdとrevisionの破棄。
- 同じ画像でエンコード1回、プロンプト推論複数回。
- エラー後のWASM／高速方式フォールバック。
- 取消とdispose後の応答無視。
- 画像変更時のキャッシュ破棄。

モデル本体は実ブラウザのスモークテストで、固定画像・固定プロンプトからマスクが得られることを確認する。

### 9.3 エディター統合テスト

- 手動レイヤーだけがダイアログを開ける。
- ロック中はファイル選択前に拒否する。
- ダイアログ中にレイヤーがロック／削除された場合は確定を拒否する。
- 取消、デコード失敗、点不足では保存状態と履歴が変化しない。
- 置換／追加を尊重する。
- 断面はダイアログ開始時の対象か、確定時の対象かを仕様どおり固定する。本計画では開始時の断面を採用する。
- 生成点が移動、削除、星置換できる。
- Undo/Redoと保存再読込後に点群が一致する。
- JSONに画像名、画像データ、マスク、指定点、モデル情報が含まれない。

### 9.4 アクセシビリティテスト

- ダイアログ開始時に見出しまたは最初の操作へフォーカスする。
- Tab/Shift+Tabがダイアログ外へ出ない。
- Escapeと取消で元ボタンへ戻る。
- 点種別、連番、位置、削除結果が読み上げられる。
- 色覚に依存せず `＋`、`−`、`★` で区別できる。
- キーボードだけで被写体1点、特徴1点、配置まで完了できる。

### 9.5 実画像とブラウザ

最低50枚を、透過PNG、単純背景、人物、動物、イラスト、複雑背景、同系色、画像端、複数被写体、穴・分離パーツへ分類する。

対象環境:

- Chrome／Edgeの対象最新版: WebGPUとWASM。
- Safari 26系: WebGPU利用可否とWASM。
- Firefox対象最新版: WebGPU利用可否とWASM。
- iOS Safari、Android Chromeの対象実機または同等環境。
- 1440×900、1280×720、1024×768、390×844、200%相当の拡大表示。

## 10. 受け入れ基準

1. 画像選択後、draftを変更せず点指定ダイアログが開く。
2. 被写体点を1〜3点、背景除外点を0〜5点、特徴点を0〜5点追加・削除できる。
3. 被写体／背景点がマスクへ、特徴点が仮想星配点へ別々に反映される。
4. 特徴予算が `特徴数 × 8` 以上あり、マスク内に十分な局所情報があれば、各特徴点は最低8点で表現される。少数予算でも各特徴の中心は最低1点で示される。
5. 外形へ総点数の最低60%を残し、総点数は設定値以下かつ240以下である。
6. すべての出力点が安全半径0.94以内にある。
7. 同一入力と同一プロバイダの結果が決定的である。
8. 確定前の取消・失敗ではdraftとUndo履歴が変化しない。
9. 確定後は通常の手動点になり、Undo 1回で生成前へ戻る。
10. schema v4を維持し、画像、マスク、指定点を保存しない。
11. 画像データを外部送信せず、モデルとWASMは自己ホストする。
12. WebGPU非対応またはモデル失敗時もWASMまたは高速方式で続行できる。
13. 390×844とキーボード操作で、点指定から配置まで完了できる。
14. lint、全テスト、format check、production buildが成功する。

## 11. リスクと対策

| リスク | 対策 |
| --- | --- |
| 初回モデル取得が長い | 1点目の後に遅延取得、容量と進捗表示、キャッシュ、高速仮マスク |
| WebGPUの端末差 | 実セッション生成で検出しWASMへ戻す。モデルPoCを採否ゲートにする |
| 推論中に点が連打される | revisionで最新だけ採用し、短いデバウンス後に再推論 |
| 古い非同期結果が別画像へ混ざる | requestId、画像ID、revisionをすべて照合 |
| モデルやGPUメモリが残る | Tensor/GPUBufferをdisposeし、ダイアログ終了またはアイドル時にWorkerを破棄 |
| 特徴点が多く外形が崩れる | 特徴5点、各16点、通常25%・必要最小保証時のみ最大40%、外形60%の上限・下限を設定 |
| 特徴周辺に線がない | 小輪または短い印へフォールバックし、プレビューで確認可能にする |
| タッチで正確に点を置けない | 拡大、パン、点のドラッグ修正、連番一覧からの削除 |
| モデル更新で結果が変わる | 重み・設定・前処理・ハッシュを固定し、保存後は再推論しない |
| モデル資産の再配布条件 | Phase 0でコードと重みを別々に確認し、ライセンス文を同梱 |
| 既存の即時生成が遅くなる | ダイアログと推論コードを動的ロードし、通常起動バンドルから分離 |
| 複数正当成分が消える | 被写体点を最大3点許可し、各点を含む成分を必ず保持 |
| 画像がデコード後に巨大 | ファイル容量に加え総画素数上限を設ける |

## 12. 対象外

- 自由線による前景／背景ブラシ。必要性が確認された場合の第2段階とする。
- 元画像のトリミング、回転、色調補正を行う本格画像エディター。
- 画像やマスクを作品へ埋め込み、後から指定点を再編集する機能。
- 画像から新しい仮想星プリセットを生成する機能。
- クラウドAPIへの画像送信。
- 1枚の画像から真の3D形状を推定し、複数断面へ展開する機能。
- 動画、複数画像、リアルタイムカメラ入力。
